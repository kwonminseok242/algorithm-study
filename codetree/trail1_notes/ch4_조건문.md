## 1. 삼항 연산자 — `if else`를 한 줄로

### 핵심 요약
- **`if` / `else`만 있는** 단순한 구문은 한 줄로 줄여 쓸 수 있다. 이걸 **삼항 연산자**(조건부 표현식)라고 한다.
- 모양은 **`값1 if 조건 else 값2`** — 조건이 **참이면 값1**, **거짓이면 값2**가 된다.
- 읽는 순서가 영어 문장과 같다. "**값1** 이다 / 만약 **조건**이면 / 아니면 **값2**"
- **값을 고르는 것**이지 명령을 실행하는 게 아니다. 그래서 `=` 오른쪽이나 `print()` 안에 바로 넣을 수 있다.

### 예시 코드

**기존 코드 (4줄)**
```python
if 조건:
    a = v1
else:
    a = v2
```

**삼항 연산자 (1줄)** ⭐
```python
a = v1 if 조건 else v2
```

**실제 예시**
```python
a = int(input())
b = 50 if a > 10 else 3
print(b)
```
```
>> 20
50
```
```
>> 5
3
```

**`print()` 안에 바로 넣어도 된다**
```python
a = int(input())
print("정답" if a == 100 else "오답")
```

**위치 비교로 외우기**
```python
b =  50  if  a > 10  else  3
#     ↑        ↑            ↑
#   참일 때    조건      거짓일 때
```

### 주의할 점
- 순서가 헷갈리기 쉽다. **조건이 가운데**다. (`if 조건: 값1` 처럼 앞에 오지 않는다)
- **`else`를 생략할 수 없다.** `a = 50 if x > 10` 은 SyntaxError.
- `elif`는 못 쓴다. 3갈래 이상은 그냥 보통 `if / elif / else`를 쓰는 게 읽기 좋다.
- 콜론(`:`)이 없다. 블록이 아니라 **한 개의 값**이기 때문.
- **선택되지 않은 쪽은 아예 계산되지 않는다.** (아래 3번에서 이 성질 때문에 에러가 숨는 경우를 본다)

## 2. 삼항 연산자의 함정 — 계산식이 통째로 묶인다

### 핵심 요약
- 삼항 연산자는 **`if` 앞의 식 전체**를 "참일 때의 값"으로 가져간다.
- `+`, `-` 같은 계산이 앞에 붙어 있으면 그 계산까지 **전부 한 덩어리**로 묶인다.
- 일부만 조건에 따라 바꾸고 싶다면 **그 부분만 괄호로 감싸야** 한다.

### 예시 코드

**😵 의도와 다르게 동작하는 경우**
```python
n = 8
a = 2 + 6 + 5 if n > 10 else 6
print(a)
```
```
6
```
→ `2 + 6 + 5`(=13) 전체가 "참일 때의 값"으로 묶였다.
→ `n > 10`이 거짓이니 `13`은 버려지고 **`6`만** 남는다.

**✅ 괄호로 조건 범위를 끊어 주기** ⭐
```python
n = 8
a = 2 + 6 + (5 if n > 10 else 6)
print(a)
```
```
14
```
→ `2 + 6`은 **항상 계산**되고, 괄호 안에서 `5` 또는 `6`만 선택된다. → `8 + 6 = 14`

**묶이는 범위 비교**
```python
a = 2 + 6 + 5 if n > 10 else 6
#   └──── 참일 때 값 ────┘      └ 거짓일 때 값

a = 2 + 6 + (5 if n > 10 else 6)
#   └항상┘   └─── 이 부분만 선택 ───┘
```

### 주의할 점
- 삼항 연산자는 **`+`, `-`, `*`, `/`보다 우선순위가 낮다.** 그래서 계산이 먼저 끝난 뒤 통째로 묶인다.
- 헷갈릴 바엔 **무조건 괄호를 치자.** 괄호는 틀리지 않는다.
- ch3에서 본 `(a + b) / (a - b)`와 같은 교훈이다 — **우선순위가 애매하면 괄호로 내 의도를 적는다.**
- 삼항 연산자를 다른 식 안에 섞어 쓸 때는 항상 `( ... if ... else ... )` 형태로 감싸는 습관을 들이자.

## 3. 오류 정리 — `pass`는 예약어, 글자는 따옴표로

> 내가 쓴 코드
> ```python
> a = int(input())
> result = pass if int(a) == 100 else failure
> ```

### 핵심 요약
- 에러의 원인은 **두 가지**다.
  1. **`pass`는 파이썬이 이미 쓰고 있는 예약어(키워드)** 다. 값이 아니라 **명령**이라서 `=` 오른쪽에 올 수 없다.
  2. `failure`는 따옴표가 없어서 **변수 이름**으로 읽힌다. 그런 변수는 만든 적이 없다.
- `pass`, `failure`처럼 **글자 그대로 출력하고 싶은 건 반드시 따옴표**로 감싼다. → `"pass"`, `"failure"`

### 예시 코드

**❌ 실제 에러**
```python
a = int(input())
result = pass if int(a) == 100 else failure
```
```
    result = pass if int(a) == 100 else failure
             ^^^^
SyntaxError: expected expression before 'if', but statement is given
```
→ "`if` 앞에는 **값**이 와야 하는데 **명령**이 왔다"는 뜻. `pass`는 값이 아니다.

**✅ 올바른 코드** ⭐
```python
a = int(input())
result = "pass" if a == 100 else "failure"
print(result)
```
```
>> 100
pass
```
```
>> 50
failure
```

**`int(a)`도 필요 없다**
```python
a = int(input())   # 여기서 이미 정수가 되었다
... if int(a) == 100 ...   # ❌ 이미 int인데 또 int
... if a == 100 ...        # ✅
```

### 주의할 점
- **`pass`의 원래 뜻**: "아무것도 하지 않는다"는 명령. 블록을 비워 둘 수 없을 때 자리만 채우는 용도다. (→ [4번](#4-pass--아무것도-하지-않는다고-적어-주기)에서 자세히)
  ```python
  if a > 10:
      pass          # 나중에 채울 자리
  else:
      print("작다")
  ```
- 예약어는 변수 이름으로도 못 쓴다: `pass`, `if`, `else`, `for`, `class`, `return`, `True`, `False`, `None` ...
- **따옴표를 빠뜨린 `failure`는 다른 에러**(`NameError`)를 낸다.
  ```python
  a = 50
  result = "pass" if a == 100 else failure
  ```
  ```
  NameError: name 'failure' is not defined
  ```
- ⚠️ **무서운 점**: 위 코드에서 `a = 100`이면 **에러가 안 난다.**
  ```python
  a = 100
  result = "pass" if a == 100 else failure
  print(result)     # pass  ← 에러 없이 잘 돌아간다!
  ```
  → 삼항 연산자는 **선택되지 않은 쪽을 아예 계산하지 않기** 때문. 오타가 숨어 있다가 다른 입력에서 터진다.
  → 예제 하나 맞았다고 안심하지 말고, **두 갈래를 모두 테스트**하자.
- 따옴표는 `"pass"`든 `'pass'`든 상관없다. 대신 **한 쌍으로 맞출 것**.

## 4. `pass` — "아무것도 하지 않는다"고 적어 주기

### 핵심 요약
- 파이썬은 `if:` / `elif:` / `else:` 아래에 **반드시 무언가 한 줄**이 있어야 한다. 그냥 비워 두면 에러다.
- 그런데 "이 경우엔 **정말 아무것도 안 하고 싶다**"는 상황이 있다. 이때 쓰는 게 **`pass`** 다.
- `pass`는 **"아무 변화도 일으키지 않는다"** 는 뜻의 명령이다. 자리만 채우고 그냥 넘어간다.
- 덕분에 **"이 경우는 일부러 비워 둔 것"** 이라는 의도를 코드에 그대로 적을 수 있다.

### 예시 코드

> a가 15보다 크면 `A`, 10~15 사이면 **아무것도 출력하지 않고**, 10보다 작으면 `B`

```python
a = int(input())

if a > 15:
    print("A")
elif a >= 10:
    pass
else:
    print("B")

print("Done")
```
```
>> 20
A
Done
```
```
>> 13
Done
```
```
>> 5
B
Done
```

→ `13`일 때 `elif` 가지로 들어가긴 했지만 `pass`라서 **아무 일도 일어나지 않고** 빠져나온다.
→ 조건문이 끝난 뒤의 `print("Done")`은 **어느 경우든 항상 실행**된다. (들여쓰기가 `if` 바깥이니까)

**❌ 비워 두면 에러**
```python
if a > 15:
    print("A")
elif a >= 10:
else:
    print("B")
```
```
    else:
    ^^^^
IndentationError: expected an indented block after 'elif' statement on line 5
```
→ "`elif` 다음에 들여쓴 줄이 있어야 한다"는 뜻. 파이썬은 **빈 블록을 허용하지 않는다.**

### 주의할 점
- `pass`는 **값이 아니라 명령**이다. `result = pass` 는 불가능. (→ [3번](#3-오류-정리--pass는-예약어-글자는-따옴표로))
- `pass`와 헷갈리기 쉬운 것들
  - `pass` → 아무것도 안 하고 **그 줄만** 넘어간다 (블록 자리 채우기)
  - `continue` → 반복문에서 **다음 회차로** 건너뛴다 (ch5 이후)
  - `break` → 반복문을 **완전히 빠져나온다** (ch5 이후)
  - → 조건문에서 쓰는 건 **`pass`** 다.
- `elif a >= 10: pass` 가지를 **아예 지워도 결과는 같다.** 다만 `a > 15` / `else` 두 갈래만 남으면 10~15 구간이 `else`로 흘러가 `B`가 출력되므로, **조건을 다시 짜야 한다.**
  ```python
  # pass를 지우려면 조건을 이렇게 바꿔야 한다
  if a > 15:
      print("A")
  elif a < 10:
      print("B")
  ```
  → 이 방식도 맞지만, `pass`를 쓰면 **"10~15는 의도적으로 무시"** 라는 게 눈에 보인다. 문제의 조건을 **정의 그대로** 옮길 때 유리하다.
- 경계값을 조심하자. `a > 15`와 `a >= 10` 사이 → **15는 `elif`(아무것도 안 함)**, 16부터 `A`다. `>`인지 `>=`인지 항상 확인할 것.
- `elif`는 **위에서부터 순서대로** 검사하고, **처음 맞는 하나만** 실행한 뒤 나머지는 건너뛴다.

## 5. `if / else` vs `if` 두 번 — "또는"인가 "순서대로"인가

### 핵심 요약
- `if / else`는 **둘 중 딱 하나만** 실행된다. 하나가 걸리면 나머지는 **쳐다보지도 않는다.**
- `if`를 **따로 두 번** 쓰면 두 조건을 **각각 처음부터 다시** 검사한다. 둘 다 실행될 수도 있다.
- 문제가 **"과정 1을 거친 뒤, 연달아 과정 2를 거친다"** 고 하면 → **`if` 두 번**이다.
- 문제가 **"짝수면 A, 홀수면 B"** 처럼 갈래를 나누면 → **`if / else`** 다.
- 결정적 차이: `if`를 두 번 쓰면 **첫 번째 `if`가 바꿔 놓은 값을 두 번째 `if`가 보고 판단**한다.

### 예시 코드

**❌ `if / else` — 둘 중 하나만 실행된다**
```python
a = int(input())
if a % 2 == 0:
    a = a // 2
else:
    a = (a + 1) // 2
print(a)
```
```
>> 10
5
```
→ 10은 짝수라 `a = 5`가 되고, **`else`는 건너뛴다.** 연산이 **1번만** 일어났다.

**✅ `if` 두 번 — 순서대로 둘 다 거친다** ⭐
```python
a = int(input())
if a % 2 == 0:
    a = a // 2
if a % 2 == 1:
    a = (a + 1) // 2
print(a)
```
```
>> 10
3
```
→ 첫 번째 `if`: 10은 짝수 → `a = 5`
→ 두 번째 `if`: **바뀐 5**를 다시 검사 → 홀수 → `a = 3`

**값이 흘러가는 모습**
```
입력 10 ─ [과정1: 짝수? O] → 5 ─ [과정2: 홀수? O] → 3
입력  8 ─ [과정1: 짝수? O] → 4 ─ [과정2: 홀수? X] → 4   (변화 없음)
입력  7 ─ [과정1: 짝수? X] → 7 ─ [과정2: 홀수? O] → 4
```

**구조 비교**
```python
if 조건A:      # ┐ 하나로 묶인 한 덩어리
    ...        # │ A가 맞으면 B는 검사조차 안 한다
else:          # │
    ...        # ┘

if 조건A:      # ← 첫 번째 판단
    ...
if 조건B:      # ← 여기서 다시 처음부터 판단 (바뀐 값 기준!)
    ...
```

### 주의할 점
- ⚠️ **일부 예제는 우연히 맞는다.** 위 `if / else` 코드도 입력이 `8`이면 `4`가 나와 **정답과 같다.**
  → 예제 하나 통과했다고 제출하지 말고, **다른 값도 손으로 굴려 보자.** (3번과 같은 교훈)
- 문제의 "**순서대로 거친 이후**", "**연달아**" 같은 말은 `if` 두 번을 쓰라는 신호다.
- 두 번째 `if`의 조건은 **바뀐 값** 기준이다. 원래 입력값이 아니다.
  → 원래 값으로 판단해야 한다면 `original = a`처럼 따로 저장해 둬야 한다.
- `else`를 `if 아닌 조건`으로 바꿔 쓴 것과 `else`는 **다르다.**
  - `if 짝수: ... / else: ...` → 하나만 실행 (else는 "나머지 전부")
  - `if 짝수: ... / if 홀수: ...` → 각각 검사 (둘 다 실행 가능)
- `elif`는 `else` 쪽이다. **`if / elif / elif`도 처음 걸리는 하나만** 실행된다. (4번 참고)

## 6. 정답 정리 — 최대 2번의 연산

> 정수 `a`를 입력받아 다음 2개의 과정을 **순서대로** 거친 결과를 출력
> 1. `a`가 **짝수**라면 2로 나눈다
> 2. `a`가 **홀수**라면 1을 더한 뒤 2로 나눈다
>
> (제한: `1 ≤ a ≤ 100`, 출력은 **소수점이 없는 정수 형태**)

```python
a = int(input())

if a % 2 == 0:
    a = a // 2

if a % 2 == 1:
    a = (a + 1) // 2

print(a)
```
```
>> 10
3
```
```
>> 8
4
```

**풀이 흐름**
1. "**순서대로 거친 이후**" → `if / else`가 아니라 **`if` 두 번** (5번)
2. 짝수 판별은 `a % 2 == 0`, 홀수 판별은 `a % 2 == 1` (ch3의 나머지 연산자)
3. 두 번째 `if`는 **1번 과정을 거친 뒤의 값**을 본다 — 이게 문제의 핵심
4. 소수점 없이 출력 → `/` 대신 **`//`** 를 쓴다

**`/`를 쓰면?**
```python
a = 10 / 2      # 5.0   ← float!
print(a)        # 5.0   ❌ 소수점이 붙는다
print(int(a))   # 5     ✅ 이렇게 고칠 수는 있다
```
- `int()`로 감싸도 정답은 나오지만, **처음부터 `//`를 쓰는 게 깔끔하다.**
- `//`를 쓰면 중간 계산도 계속 정수라 `a % 2` 판별이 안전하다.
- ⚠️ `/`를 쓰면 `a`가 `5.0`(float)이 되고, 그 뒤 `5.0 % 2 == 1.0`은 **`True`이긴 하다.** 그래도 정수 문제에 float를 섞으면 나중에 꼭 탈이 난다.

**손으로 검산해 보기**
| 입력 | 과정 1 (짝수?) | 과정 2 (홀수?) | 출력 |
|---|---|---|---|
| 10 | O → 5 | O → 3 | **3** |
| 8 | O → 4 | X | **4** |
| 7 | X | O → 4 | **4** |
| 1 | X | O → 1 | **1** |
| 100 | O → 50 | X | **50** |

## 7. 비교 연산의 결과는 그 자체가 `True`/`False`

### 핵심 요약
- `a >= b` 같은 **비교식은 그 자체로 이미 값**이다. 결과는 `True` 또는 `False` (자료형: `bool`).
- `if`는 그 값을 보고 갈라질 뿐이다. 즉 **`if`가 True/False를 만드는 게 아니다.**
- 파이썬에서 **`True`는 `1`, `False`는 `0`** 과 같다. 그래서 `int()`로 감싸면 바로 `1`/`0`이 나온다.
- 결론: **"참이면 1, 거짓이면 0을 출력"은 `if / else` 없이 `print(int(비교식))` 한 줄이면 끝난다.**

### 예시 코드

**😵 if / else로 쓰면 — 6줄짜리가 6번 반복된다**
```python
if a >= b:
    print("1")
else:
    print("0")
```

**✅ 방법 ① `int()`로 감싸기 ⭐ (가장 짧다)**
```python
print(int(a >= b))
```

**✅ 방법 ② 삼항 연산자 (1번 개념 활용)**
```python
print(1 if a >= b else 0)
```

**왜 되는지 — 한 단계씩 뜯어보기**
```python
a, b = 10, 5

print(a >= b)          # True        ← 비교식 자체가 값이다
print(type(a >= b))    # <class 'bool'>
print(int(True))       # 1
print(int(False))      # 0
print(int(a >= b))     # 1           ← 합치면 이것
```

**`True == 1`이라는 증거**
```python
print(True + True)   # 2
print(True * 3)      # 3
print(True == 1)     # True
```

### 주의할 점
- ⚠️ **그냥 출력하면 `1`이 아니라 `True`가 찍힌다.** 문제가 `1`/`0`을 요구하면 **반드시 `int()`로 감싸야** 한다.
  ```python
  print(a >= b)        # True   ❌ 오답
  print(int(a >= b))   # 1      ✅
  ```
- 비교 연산자 6종: `>` `<` `>=` `<=` `==` `!=`
  - `==`(같다)와 `=`(대입)는 **완전히 다르다.** `if a = b:`는 SyntaxError.
  - `>=`이지 `=>`가 아니다. 등호가 **뒤**에 온다.
- **문제에 적힌 순서 그대로** 조건을 쓰는 게 안전하다.
  - "A가 B보다 큰가?" → `a > b` ✅ (`b < a`도 같은 뜻이지만 읽다가 헷갈린다)
- `!=`는 "다르다"이고, `==`의 반대다. `not (a == b)`와 같다.
- 입력은 ch3에서 배운 `map`으로 한 줄에 끝내자: `a, b = map(int, input().split())`
- 출력값이 숫자 `1`이면 따옴표 없이 `1`을 쓰자. `print("1")`도 화면엔 똑같이 보이지만, 굳이 문자열로 만들 이유가 없다.

## 8. 정답 정리 — 비교 연산

> 두 정수 `A`, `B`를 입력받아 6개 조건의 참/거짓을 **각 줄에** 출력 (참이면 `1`, 거짓이면 `0`)
> ① `A >= B` ② `A > B` ③ `B >= A` ④ `B > A` ⑤ `A == B` ⑥ `A != B`
> (제한: `1 ≤ A, B ≤ 100`)

**내가 쓴 코드 — 정답이다. 다만 36줄** 👍
```python
a, b = input().split()
a = int(a)
b = int(b)

if a >= b:
    print("1")
else:
    print('0')
...
```
→ 논리는 하나도 틀리지 않았다. **줄이는 방법을 몰랐을 뿐.**

**✅ 줄인 코드 (7줄)** ⭐
```python
a, b = map(int, input().split())

print(int(a >= b))
print(int(a > b))
print(int(b >= a))
print(int(b > a))
print(int(a == b))
print(int(a != b))
```
```
>> 10 5
1
1
0
0
0
1
```

**무엇을 줄였나**
| 줄인 부분 | 전 | 후 |
|---|---|---|
| 입력 + 정수 변환 | 3줄 (`split()` → `int()` 2번) | 1줄 (`map`, ch3) |
| 조건 1개당 | 4줄 (`if/else`) | 1줄 (`int(비교식)`) |
| 전체 | 약 30줄 | **7줄** |

**참고 — 반복문을 배우면 더 줄어든다 (ch5 이후)**
```python
a, b = map(int, input().split())
for c in [a >= b, a > b, b >= a, b > a, a == b, a != b]:
    print(int(c))
```
→ 지금은 몰라도 된다. "비교식을 **값처럼 담아 둘 수 있다**"는 것만 기억해 두자.

**풀이 흐름**
1. 한 줄에 두 수 → `map(int, input().split())` (ch3)
2. 조건 6개를 **문제에 적힌 순서 그대로** 쓴다
3. 참/거짓을 `1`/`0`으로 → **`int()`로 감싼다** (7번)
4. 각 줄에 출력 → `print()`를 6번 (`print`는 기본으로 줄바꿈)

## 9. `and` / `or` — 조건 여러 개를 묶기 (범위 판별)

### 핵심 요약
- 조건 **2개 이상을 동시에** 만족하는지 보고 싶을 때 → **`and`** (그리고)
- **둘 중 하나라도** 만족하면 될 때 → **`or`** (또는)
- "`a`가 2 이상 10 이하"처럼 **범위**를 묻는 건 사실 조건 **2개**다. → `2 <= a and a <= 10`
- 파이썬은 `2 <= a <= 10` 처럼 **이어 쓰는 것도 허용**하지만, 이건 **파이썬만의 특별한 문법**이다.
  → 다른 언어에는 없으므로 **조건이 2개 이상이면 `and`로 나눠 쓰는 습관**을 들이자.

### 예시 코드

**✅ `and`로 나눠 쓰기 (권장) ⭐**
```python
a = int(input())

if 2 <= a and a <= 10:
    print("in range")
else:
    print("out of range")
```
```
>> 10
in range
```
```
>> 1
out of range
```

**✅ 파이썬식으로 이어 쓰기 (짧지만 파이썬 전용)**
```python
if 2 <= a <= 10:
    print("in range")
```

**`and` / `or` 결과표**
```python
True  and True   # True    ← and는 둘 다 참이어야 참
True  and False  # False
False and True   # False
False and False  # False

True  or True    # True     ← or는 하나만 참이어도 참
True  or False   # True
False or True    # True
False or False   # False
```

**범위를 그림으로**
```
        2 <= a            a <= 10
    ────────●━━━━━━━━━━━━━━●────────
            2             10
            └── and로 묶인 구간 ──┘   → "in range"
```

### 주의할 점
- ⚠️ **가장 흔한 실수: 조건을 끝까지 쓰지 않는 것**
  ```python
  if a == 2 or 3:      # ❌ "a가 2이거나 3이면" 이라는 뜻이 아니다!
  ```
  ```python
  a = 99
  if a == 2 or 3:
      print("참으로 판정됨!")   # ← a가 99인데도 출력된다!
  ```
  → 파이썬은 이걸 `(a == 2) or (3)`으로 읽는다. 그런데 **0이 아닌 숫자는 전부 참**(`bool(3)` → `True`)이라
  **무조건 참**이 되어 버린다. 에러도 안 난다. **제일 무서운 종류의 버그.**
  ```python
  if a == 2 or a == 3:   # ✅ 양쪽 모두 완전한 비교식으로
  ```
  → **`or` / `and` 양옆에는 각각 완전한 비교식**을 쓴다. 변수 이름을 생략할 수 없다.
- `2 <= a and a <= 10` 에서 **`a`가 두 번 나온다.** 한 번만 쓰면 위와 같은 함정에 빠진다.
- `and`, `or`는 **영어 단어 그대로** 쓴다. `&&`, `||`는 파이썬이 아니다.
- **범위 밖**을 판별할 땐 부등호 방향이 뒤집히고 `and`가 `or`로 바뀐다.
  ```python
  a < 2 or a > 10        # 범위 밖 (or!)
  not (2 <= a <= 10)     # 같은 뜻
  ```
  → `and`를 그대로 두고 부등호만 뒤집으면 **절대 참이 될 수 없는 조건**이 된다. (`a < 2 and a > 10`)
- **"이상/이하"는 `=`가 붙고, "초과/미만"은 안 붙는다.**
  - 2 **이상** → `a >= 2` / 2 **초과** → `a > 2`
  - 10 **이하** → `a <= 10` / 10 **미만** → `a < 10`
  → 경계값(`2`, `10`)을 직접 넣어 보고 확인하는 습관을 들이자.
- `and`/`or`의 결과도 결국 `True`/`False`다. → `print(int(2 <= a <= 10))` 처럼 쓸 수도 있다. (7번)

## 10. 오류 정리 — `IndentationError`, 들여쓰기는 "문법"이다

> 내가 쓴 코드
> ```python
>  a = int(input())
>
>  print('yes') if a >= 10 and a <=20 else print('no')
> ```
> ```
> File "/tmp/Main.py", line 1
>     a = int(input())
> IndentationError: unexpected indent
> ```

### 핵심 요약
- **`unexpected indent` = "여기 들여쓰기를 할 이유가 없는데 칸이 띄어져 있다"** 는 뜻이다.
- 원인은 딱 하나. 첫 줄 맨 앞에 **공백 한 칸**이 들어가 있었다. (` a = int(input())`)
- 파이썬에서 **들여쓰기는 꾸밈이 아니라 문법**이다. 어디에 속하는지를 칸으로 표시한다.
- `if:` 같은 **콜론으로 끝나는 줄 다음에만** 들여쓴다. 그 외에는 **맨 왼쪽에 붙여야** 한다.
- 에러 메시지의 `line 1`은 **"1번째 줄을 보라"** 는 뜻이다. 눈에 안 보이는 문제일수록 줄 번호부터 확인하자.

### 예시 코드

**❌ 앞에 공백이 하나 있는 경우**
```python
 a = int(input())
```
```
    a = int(input())
IndentationError: unexpected indent
```
→ 코드 자체는 완벽하다. **맨 앞 공백 한 칸** 때문에 실행조차 되지 않은 것.

**✅ 맨 왼쪽에 붙이기 ⭐**
```python
a = int(input())
print('yes') if a >= 10 and a <= 20 else print('no')
```
```
>> 15
yes
```

**들여쓰기가 "필요한" 자리와 "안 되는" 자리**
```python
a = int(input())      # ← 맨 왼쪽 (들여쓰기 X)

if a >= 10:           # ← 맨 왼쪽, 콜론으로 끝남
    print("크다")      # ← 콜론 다음이니까 들여쓰기 O (4칸)
else:                 # ← if와 같은 높이로 맨 왼쪽
    print("작다")      # ← 들여쓰기 O

print("끝")           # ← 조건문 밖이니까 다시 맨 왼쪽
```

### 주의할 점
- 공백은 **눈에 보이지 않는다.** 에러 메시지에 코드가 멀쩡해 보이면 **맨 앞 커서 위치**부터 확인하자.
  → 줄 맨 앞에서 `Home` 키를 누른 뒤 커서가 글자에 바로 붙는지 보면 된다.
- 복사·붙여넣기를 하면 **앞쪽 공백이 딸려 오는 일이 매우 흔하다.** 이 에러의 1순위 원인.
- 들여쓰기는 **공백 4칸**으로 통일한다. 탭과 공백을 **섞으면** `TabError`가 난다.
- 같은 블록 안의 줄들은 **칸 수가 정확히 같아야** 한다. 한 칸만 달라도 에러다.
- 들여쓰기 관련 에러 3형제
  - `unexpected indent` → 들여쓰면 안 되는데 들여씀 (이번 경우)
  - `expected an indented block` → 들여써야 하는데 비어 있음 (4번의 `pass` 참고)
  - `unindent does not match any outer indentation level` → 칸 수가 위와 안 맞음
- 참고 — **`print()`를 삼항 연산자 양쪽에 두는 건 되긴 하지만 권장되지 않는다.**
  ```python
  print('yes') if a >= 10 else print('no')          # 돌아가긴 한다
  print('yes' if 10 <= a and a <= 20 else 'no')     # ✅ 이 쪽이 낫다
  ```
  → 삼항 연산자는 **값을 고르는** 도구다 (1번). **고른 값을 `print`가 받는** 모양이 자연스럽다.
  → `print()`를 양쪽에 두면 "값"이 아니라 "명령"을 고르는 셈이라 의도가 흐려진다.
  (실제로 `x = print('hi') if True else print('bye')` 하면 `x`에는 `None`이 담긴다.)

## 11. `and` / `or` 연산자 우선순위 — `and`가 먼저다

### 핵심 요약
- 괄호가 없으면 **`and`가 `or`보다 먼저** 묶인다.
- 즉 `A and B or C` 는 **`(A and B) or C`** 로 읽힌다.
- 외우는 법: **`and`는 곱하기(`*`), `or`는 더하기(`+`)** 라고 생각하면 순서가 똑같다.
  - `2 * 3 + 4` = `(2 * 3) + 4` ↔ `A and B or C` = `(A and B) or C`
- 헷갈릴 바엔 **괄호를 직접 치자.** 2번에서 본 것과 같은 교훈이다.

### 예시 코드

**괄호 없는 코드**
```python
if a % 2 == 0 and a % 5 == 0 or a % 7 == 0:
    코드1
```

**파이썬이 실제로 읽는 방식 — 정확히 같은 코드다**
```python
if (a % 2 == 0 and a % 5 == 0) or a % 7 == 0:
    코드1
```
→ "**(2의 배수이면서 5의 배수)** 이거나 **7의 배수**"

**실행 예시**
```python
a = int(input())

if a % 2 == 0 and a % 5 == 0 or a % 7 == 0:
    print("special")
else:
    print("normal")
```
```
>> 10
special
```
→ 10은 2의 배수 **이고** 5의 배수 → 앞쪽 `and`가 참
```
>> 21
special
```
→ 21은 짝수가 아니라 앞쪽 `and`는 거짓. 하지만 **7의 배수**라서 `or`로 참이 된다.

**⚠️ 괄호를 다르게 치면 답이 달라진다**
```python
a = 21

(a % 2 == 0 and a % 5 == 0) or a % 7 == 0    # True   ← 기본 해석
a % 2 == 0 and (a % 5 == 0 or a % 7 == 0)    # False  ← 다른 뜻!
```
| a | `(and) or` ← 기본 | `and (or)` |
|---|---|---|
| 10 | True | True |
| 20 | True | True |
| 14 | True | True |
| **21** | **True** | **False** ← 다름! |
| **35** | **True** | **False** ← 다름! |
| 3 | False | False |

→ 어떤 값에서는 똑같이 나오다가 **특정 값에서만 갈라진다.** 제일 찾기 힘든 버그다.

**우선순위 전체 순서 (높은 것부터)**
```
1. 산술      +  -  *  /  //  %
2. 비교      >  <  >=  <=  ==  !=
3. not
4. and
5. or
```
```python
a % 2 == 0          # (a % 2) == 0        ← %가 ==보다 먼저라 괄호 없이도 된다
not True and False  # (not True) and False → False
```

### 주의할 점
- **괄호가 없어도 `a % 2 == 0`은 안전하다.** 산술(`%`)이 비교(`==`)보다 먼저이기 때문.
  → 오히려 `a % (2 == 0)`처럼 엉뚱하게 괄호를 치면 `ZeroDivisionError`가 난다.
- `and`/`or`를 **섞어 쓸 때만** 괄호를 신경 쓰면 된다. 같은 것끼리(`A and B and C`)는 순서가 상관없다.
- 우선순위를 외우기보다 **괄호를 치는 습관**이 낫다. 읽는 사람(=나중의 나)도 편하다.
- 코드를 검증할 땐 **양쪽 해석이 갈라지는 값**을 직접 넣어 보자. (위 표의 `21`, `35`)
- 9번의 `if a == 2 or 3:` 함정도 결국 우선순위 이야기다. → `(a == 2) or (3)`

- [ ] **`else`는 생략 불가**, `elif`는 쓸 수 없다, 콜론(`:`)도 없다.
- [ ] `print()` 안에도 `=` 오른쪽에도 바로 넣을 수 있다 (값이니까).
- [ ] `2 + 6 + 5 if n > 10 else 6` → `2+6+5` 전체가 한 덩어리로 묶인다.
- [ ] 일부만 조건에 따라 바꾸려면 **`2 + 6 + (5 if n > 10 else 6)`** 처럼 괄호로 끊는다.
- [ ] 삼항 연산자는 사칙연산보다 **우선순위가 낮다**. 헷갈리면 무조건 괄호. (ch3 교훈 재등장)
- [ ] **`pass`는 예약어**다. 값이 아니라 명령이라 `=` 오른쪽에 못 온다.
- [ ] 글자 그대로 쓸 값은 반드시 따옴표로: `"pass"`, `"failure"`
- [ ] 따옴표 없는 이름은 **변수**로 읽힌다 → `NameError: name 'failure' is not defined`
- [ ] `a = int(input())` 했으면 이후에 **또 `int(a)`를 할 필요 없다**.
- [ ] 삼항 연산자는 **선택되지 않은 쪽을 계산하지 않는다** → 오타가 숨을 수 있으니 **양쪽 다 테스트**.
- [ ] `SyntaxError`는 문법이 틀린 것, `NameError`는 없는 이름을 부른 것.
- [ ] `if` / `elif` / `else` 블록은 **비워 둘 수 없다** → `IndentationError`
- [ ] "아무것도 하지 않기"를 적고 싶으면 **`pass`** 를 쓴다.
- [ ] `pass`는 자리만 채우고 넘어가는 **명령**이다 (값이 아니다).
- [ ] `pass`(자리 채우기) ↔ `continue`(다음 회차) ↔ `break`(탈출) — 셋을 구분하자.
- [ ] `elif`는 위에서부터 검사해 **처음 맞는 하나만** 실행한다.
- [ ] 조건문이 끝난 뒤의 줄은 **들여쓰기가 바깥**이면 항상 실행된다.
- [ ] 경계값(`>` vs `>=`)을 항상 확인하자. `a > 15`면 **15는 포함되지 않는다**.
- [ ] `if / else`는 **둘 중 하나만** 실행, `if` 두 번은 **각각 검사**한다.
- [ ] 문제에 "**순서대로**", "**연달아**"가 있으면 → **`if` 두 번**.
- [ ] `if`를 두 번 쓰면 두 번째는 **첫 번째가 바꿔 놓은 값**을 보고 판단한다.
- [ ] 원래 입력값이 필요하면 `original = a`로 **따로 저장**해 둔다.
- [ ] 짝수는 `a % 2 == 0`, 홀수는 `a % 2 == 1` (ch3 나머지 연산자).
- [ ] 정수로 출력해야 하면 `/`가 아니라 **`//`** 를 쓴다. (`/`는 항상 float → `5.0`)
- [ ] `if / else`로 써도 **어떤 예제는 우연히 맞는다.** 값을 여러 개 손으로 굴려 보자.
- [ ] `a >= b` 같은 **비교식 자체가 이미 값**이다 (`True` / `False`, 자료형은 `bool`).
- [ ] 파이썬에서 **`True` = `1`, `False` = `0`**. `True + True`는 `2`다.
- [ ] "참이면 1, 거짓이면 0 출력" → **`print(int(비교식))`** 한 줄이면 끝.
- [ ] ⚠️ 그냥 `print(a >= b)`하면 `1`이 아니라 **`True`**가 찍힌다. `int()` 필수.
- [ ] 삼항 연산자로도 가능: `print(1 if a >= b else 0)` (1번)
- [ ] 비교 연산자 6종: `>` `<` `>=` `<=` `==` `!=`
- [ ] `==`(같다)와 `=`(대입)는 다르다. `>=`이지 `=>`가 아니다.
- [ ] 조건은 **문제에 적힌 순서 그대로** 쓰자 (`A > B`를 `b < a`로 뒤집지 말기).
- [ ] 입력은 `a, b = map(int, input().split())` 한 줄로 (ch3).
- [ ] 조건 2개를 **동시에** 만족 → `and`, **하나라도** 만족 → `or`.
- [ ] "2 이상 10 이하"는 조건 **2개**다 → `2 <= a and a <= 10`.
- [ ] `2 <= a <= 10`도 되지만 **파이썬 전용 문법**. 습관은 `and`로 나눠 쓰기.
- [ ] ⚠️ `if a == 2 or 3:` 는 **항상 참**이 된다 (에러도 안 남). → `if a == 2 or a == 3:`
- [ ] `or`/`and` 양옆에는 **각각 완전한 비교식**을 쓴다. 변수를 생략할 수 없다.
- [ ] 0이 아닌 숫자는 전부 참으로 취급된다 (`bool(3)` → `True`).
- [ ] `and`/`or`는 영어 단어 그대로. `&&`, `||`는 파이썬이 아니다.
- [ ] 범위 **밖**은 부등호를 뒤집고 `and` → **`or`** 로 바꾼다. (`a < 2 or a > 10`)
- [ ] 이상/이하는 `=`가 붙고(`>=`, `<=`), 초과/미만은 안 붙는다(`>`, `<`). 경계값을 넣어 확인!
- [ ] `IndentationError: unexpected indent` → **들여쓸 자리가 아닌데 칸이 띄어져 있다**.
- [ ] 파이썬에서 **들여쓰기는 문법**이다. 공백 한 칸에도 실행이 멈춘다.
- [ ] **콜론(`:`)으로 끝난 줄 다음에만** 들여쓴다. 나머지는 맨 왼쪽.
- [ ] 코드가 멀쩡해 보이는 에러는 **줄 맨 앞 공백**부터 의심하자 (복사·붙여넣기 1순위 원인).
- [ ] 들여쓰기는 **공백 4칸**으로 통일. 탭과 섞으면 `TabError`.
- [ ] `unexpected indent`(넘침) ↔ `expected an indented block`(비어 있음)을 구분하자.
- [ ] 에러 메시지의 `line N`은 **N번째 줄을 보라**는 뜻이다.
- [ ] 삼항 연산자는 **값**을 고르는 것: `print('yes' if 조건 else 'no')` ✅
- [ ] 괄호가 없으면 **`and`가 `or`보다 먼저** 묶인다 → `A and B or C` = `(A and B) or C`.
- [ ] 외우는 법: **`and` = 곱하기, `or` = 더하기.** `2*3+4`와 같은 순서.
- [ ] 우선순위: **산술 → 비교 → `not` → `and` → `or`**
- [ ] `a % 2 == 0`은 괄호 없이 안전하다 (`%`가 `==`보다 먼저).
- [ ] `and`/`or`를 **섞어 쓸 때만** 괄호를 신경 쓰면 된다.
- [ ] 괄호를 다르게 치면 **특정 값에서만** 답이 갈린다 (`21`, `35`). 가장 찾기 힘든 버그.
- [ ] 우선순위를 외우기보다 **괄호를 치는 습관**을 들이자. (2번과 같은 교훈)
