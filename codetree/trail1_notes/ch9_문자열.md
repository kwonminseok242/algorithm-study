## 1. 공백으로 나눠 여러 개 입력받기 — `split()` / 언패킹 / `tuple()`

### 핵심 요약

- ⭐⭐ **일을 하는 건 `split()` 하나뿐이다.** `map`도 `tuple`도 `list`도 **덤**이다.

  ```python
  input().split()        # 'banana apple'  →  ['banana', 'apple']
  ```

  `split()`은 **공백을 기준으로 잘라서 리스트를 만든다.** 여기까지가 "나누기"의 전부.

- ⭐ **`map(int, ...)` 은 "나누는" 함수가 아니라 "타입을 바꾸는" 함수다.**
  `split()`이 돌려주는 건 **언제나 문자열**이라서, 숫자로 쓰려면 한 번 더 변환해야 했던 것뿐이다.

  ```python
  a, b = map(int, input().split())    # 숫자로 쓸 거니까 int로 변환  ⭐
  a, b = input().split()              # 문자열 그대로 쓸 거면 변환 자체가 불필요  ⭐
  ```

  → **문자열 문제에서는 `map`을 쓸 이유가 없다.** 이미 문자열이니까.

- ⭐ 왼쪽에 변수를 **개수에 맞춰 나열**하면 알아서 하나씩 들어간다. 이걸 **언패킹**이라 한다.

  ```python
  a, b = input().split()
  print(a)      # banana
  print(b)      # apple
  ```

- `tuple(input().split())` 도 **똑같이 동작한다.** 다만 **없어도 된다.**
  언패킹은 리스트든 튜플이든 **가리지 않기** 때문이다.

  ```python
  a, b = tuple(input().split())   # 동작함 (코드트리 Side Note)
  a, b = list(input().split())    # 이것도 동작함
  a, b = input().split()          # ⭐ 가장 짧고 가장 흔한 형태
  ```

### 한눈에 보는 구조

```
  input()  .  split()  →  ['banana', 'apple']
    ↓          ↓
  한 줄 읽기   공백으로 자르기 (결과는 항상 "문자열" 리스트)

           ┌ 숫자로 쓸 건가? ──→ map(int, ...) 를 씌운다
           └ 문자 그대로?   ──→ 아무것도 안 씌운다   ⭐
```

| 쓰는 법 | 결과 | 언제 |
| --- | --- | --- |
| `input().split()` | `['banana', 'apple']` | **문자열** 여러 개 |
| `a, b = input().split()` | `a='banana'`, `b='apple'` | 개수를 **아는** 문자열 |
| `map(int, input().split())` | `10`, `20` (숫자) | **숫자** 여러 개 |
| `list(map(int, input().split()))` | `[10, 20, 30]` | 개수를 **모르는** 숫자 (ch7) |

### 예시 코드

**① 문자열 두 개 받아서 각각 출력 (Side Note 그대로)**

```python
a, b = input().split()      # banana apple
print(a)                    # banana
print(b)                    # apple
```

**② 더 긴 문자열 — 내가 쓴 코드를 줄여 보면 ⭐**

```python
# 내가 쓴 코드
a = list(input().split())
if len(a[0]) > len(a[1]):
    ...

# 줄인 코드
a, b = input().split()      # ⭐ list() 도, 인덱스 [0] [1] 도 필요 없다
if len(a) > len(b):
    print(a, len(a))
elif len(a) < len(b):
    print(b, len(b))
else:
    print('same')
```

- ⚠️ **`list(input().split())` 의 `list()`는 아무 일도 안 한다.** `split()`이 **이미 리스트**를 돌려주기 때문.
  (`map`은 리스트가 아니라서 `list()`가 필요했던 것 — 거기서 생긴 습관이 옮겨붙기 쉽다.)
- 이름을 `a[0]`, `a[1]` 대신 **`a`, `b`로 붙이면** 조건문이 훨씬 읽기 쉬워진다.

**③ 개수가 많거나 모를 때는 리스트로 받는다**

```python
words = input().split()           # ['사과', '바나나', '포도', ...]
print(len(words))                 # 단어가 몇 개인지
for w in words:
    print(w, len(w))
```

**④ 공백 말고 다른 글자로 자르기 — `split('구분자')`**

```python
'2026-10-05'.split('-')      # ['2026', '10', '05']
'a,b,c'.split(',')           # ['a', 'b', 'c']
```

**⑤ 반대로 합치기 — `'구분자'.join(리스트)` (ch8 복습)**

```python
words = ['banana', 'apple']
print(' '.join(words))       # banana apple
print(*words)                # banana apple   ← 공백이면 이게 더 간단
```

- `split`과 `join`은 **정확히 반대**다. **자를 땐 `split`, 붙일 땐 `join`**.

### 리스트 vs 튜플 — 왜 굳이 `tuple`을 보여줬나

| 구분 | 리스트 `[ ]` | 튜플 `( )` |
| --- | --- | --- |
| 수정 | **가능** (`a[0] = 'x'`) | **불가능** (TypeError) |
| 만들기 | `split()`의 기본 결과 | `tuple(...)` 로 변환해야 함 |
| 언패킹 | 됨 | 됨 |

- 즉 **"바꿀 일이 없는 값"** 이라는 표시일 뿐, 이 문제에서는 **기능 차이가 없다.**
- 코딩테스트에서는 **`a, b = input().split()`** 한 줄로 쓰면 된다. `tuple()`은 **읽을 줄만 알면 충분**하다.

### 주의할 점

- ⚠️⭐ **개수가 맞지 않으면 ValueError**가 난다. 언패킹은 **왼쪽 변수 수 = 오른쪽 값 수** 여야 한다.

  ```python
  a, b = input().split()      # 입력이 'banana' 하나면
  # ValueError: not enough values to unpack (expected 2, got 1)
  # 입력이 'a b c' 세 개면
  # ValueError: too many values to unpack (expected 2)
  ```

  → **입력이 한 줄에 몇 개인지** 문제에서 먼저 확인하고 변수 개수를 맞춘다.
- ⚠️⭐ **한 줄에 하나씩** 주어지면 `split()`을 쓰면 안 된다. **`input()`을 그 횟수만큼** 부른다.

  ```python
  a = input()                 # 첫째 줄
  b = input()                 # 둘째 줄    ⭐ 줄이 다르면 split이 아니다
  ```

- ⚠️ `split()`의 결과는 **무조건 문자열**이다. `'10' + '20'` 은 `30`이 아니라 **`'1020'`**.
  숫자로 계산할 거면 **반드시 `int()` / `map(int, ...)`**.
- ⚠️ `split()`은 **괄호를 비워 두면 공백 기준**이고, 공백이 **여러 칸이어도 알아서** 처리한다.
  하지만 `split(' ')` 이라고 **직접 적으면** 빈 문자열이 끼어든다.

  ```python
  'a  b'.split()        # ['a', 'b']        ⭐ 안전
  'a  b'.split(' ')     # ['a', '', 'b']    ⚠️ 빈 칸이 원소로 남는다
  ```

- ⚠️ `input().split()` 뒤에 `list()`를 씌우는 건 **불필요**. `map` 뒤에만 필요하다.
- ⚠️ `map`은 **한 번 쓰면 사라진다.** 두 번 쓸 거면 `list()`로 받아 둔다. (ch7)
- ⚠️ 입력 끝의 줄바꿈·공백이 신경 쓰이면 **`input().strip()`** — 단, `split()`을 쓰면 **이미 정리**된다.

## 2. 연속된 글자 묶어 세기(문자열 압축) — 마지막 묶음은 루프 밖에서

### 핵심 요약

- ⭐⭐ **"연속된 덩어리를 세는 문제"의 구조는 언제나 똑같다.**

  ```
  글자를 하나씩 보면서
    앞 글자와 같다  → 세던 개수를 늘린다          (cnt += 1)
    앞 글자와 다르다 → 세던 걸 결과에 넣고, 새로 시작  (append → cnt = 1)
  루프가 끝나면
    마지막 묶음이 아직 안 들어갔다 → 한 번 더 넣는다  ⭐⭐
  ```

- ⭐⭐ **마지막 묶음은 루프 안에서 절대 안 끝난다.**
  묶음은 **"다른 글자를 만나는 순간"** 결과에 들어가는데, **마지막 묶음 뒤에는 다른 글자가 없기** 때문이다.
  → **루프가 끝난 뒤에 `append`를 한 번 더** 해 주는 것이 정답이고, 이게 이 문제의 전부다.
- ⚠️ 그래서 **"마지막 글자일 때"를 루프 안에서 `if`로 특별 취급하면 꼬인다.**
  마지막 글자는 **"앞과 같은 글자"일 수도, "새 묶음의 시작"일 수도** 있는데, 한 가지로만 처리하게 되기 때문.

### 예시 코드

**① 정답 틀 ⭐ (이 형태로 외워 두기)**

```python
A = input()

arr = []
ex = A[0]                     # ex = 지금 세고 있는 글자
cnt = 0                       # cnt = 그 글자가 몇 번 연속됐나

for c in A:
    if c == ex:
        cnt += 1              # 같으면 계속 센다
    else:
        arr.append(f"{ex}{cnt}")   # 다르면 세던 걸 확정하고
        ex = c                     # 새 묶음 시작
        cnt = 1

arr.append(f"{ex}{cnt}")      # ⭐⭐ 마지막 묶음 — 루프 밖에서 한 번 더

result = ''.join(arr)
print(len(result))
print(result)
```

- `cnt = 0`으로 시작하고 **첫 글자부터 루프에 넣으면** 첫 바퀴에서 `c == ex`라 `cnt = 1`이 된다.
  (`cnt = 1`로 시작하고 `A[1:]`부터 도는 방식도 있지만, 위 형태가 **경계가 덜 헷갈린다.**)

**② 배열 없이 문자열로 바로 이어 붙이기**

```python
A = input()
result = ''
ex = A[0]
cnt = 0

for c in A:
    if c == ex:
        cnt += 1
    else:
        result += ex + str(cnt)
        ex = c
        cnt = 1
result += ex + str(cnt)       # ⭐ 여기도 똑같이 루프 밖에서

print(len(result))
print(result)
```

- ⭐ **길이는 따로 세지 않는다.** 완성된 문자열에 **`len()`** 을 씌우면 끝.

**③ 인덱스로 도는 방식 — "다음 글자와 비교"**

```python
A = input()
result = ''
cnt = 1

for i in range(len(A)):
    if i + 1 < len(A) and A[i] == A[i + 1]:   # ⚠️ 범위 검사를 먼저
        cnt += 1
    else:
        result += A[i] + str(cnt)             # 다음이 다르거나 끝이면 확정
        cnt = 1

print(len(result))
print(result)
```

- 이 방식은 **마지막 글자가 `else`로 자연스럽게 빠져서** 루프 밖 `append`가 필요 없다.
- ⚠️ 대신 **`i + 1 < len(A)` 를 반드시 `and` 앞에** 둔다. 뒤에 두면 IndexError.
  (파이썬은 `and` 왼쪽이 False면 오른쪽을 **아예 보지 않는다** — 이걸 이용한 패턴이다.)

### 오류 정리 — 내가 쓴 코드가 틀렸던 이유

```python
for i in A:
    cnt1 += 1
    if cnt1 == len(A):                      # ① 마지막 글자를 맨 먼저 가로챈다
        arr.append(f"{ex}{cnt+1}")          # ② 무조건 앞 묶음에 +1 해 버린다
    elif ex == i:
        cnt += 1
    elif ex != i:
        arr.append(f"{ex}{cnt}")
        cnt = 1
        ex = i
```

**실제 결과**

| 입력 | 내 코드 | 정답 |
| --- | --- | --- |
| `abccdabba` | `12` / `a1b1c2d1a1b3` | `14` / `a1b1c2d1a1b2a1` |
| `abcd` | `6` / `a1b1c2` | `8` / `a1b1c1d1` |
| `aabb` | `4` / `a2b2` | `4` / `a2b2` ✅ (우연히 맞음) |

- **①⭐ 순서가 거꾸로다.** `if cnt1 == len(A)` 가 **맨 위**에 있어서, 마지막 글자는
  **같은 글자인지 다른 글자인지 비교조차 못 하고** 빠져나간다.
- **②⭐ `cnt+1`은 "마지막 글자가 앞과 같다"고 **멋대로 가정**한 식**이다.
  `abccdabba`의 마지막 `a`는 앞의 `b`와 **다른 글자**인데도 `b`의 개수에 더해져 **`b3`** 이 됐다.
  그 결과 **마지막 `a1`은 통째로 사라졌다.** (12 vs 14의 차이 = 사라진 `a1`)
- `aabb`가 맞은 건 **마지막 글자가 마침 앞과 같아서**다. ⚠️ **우연히 맞는 테스트에 속으면 안 된다.**
- **③ `cnt1`은 필요 없다.** 몇 번째인지 세려고 변수를 하나 더 만들었지만,
  **마지막을 특별 취급하지 않는 것**이 정답이라 애초에 셀 이유가 없다.
- **④ `elif ex != i` 는 `else`로 충분하다.** 같지 않은 경우는 **그것 하나뿐**이다.
- **⑤ 길이를 구하려고 `for`를 한 번 더 돌았다.** → **`len(''.join(arr))`** 한 줄.
- **⚠️⑥ `sum` 을 변수 이름으로 썼다.** 파이썬 **내장 함수 이름**이라 그 아래에서 `sum([1,2])` 가
  **에러**가 난다. (`list`, `str`, `max`, `min`, `len`, `input`도 마찬가지)

### 같은 틀로 풀리는 문제들

- **가장 긴 연속 구간의 길이** — `append` 대신 `best = max(best, cnt)`
- **연속된 덩어리가 몇 개인가** — `append` 대신 `groups += 1`
- **압축 해제** (`a3` → `aaa`) — `글자 * int(숫자)`

```python
# 가장 긴 연속 구간
ex, cnt, best = A[0], 0, 0
for c in A:
    cnt = cnt + 1 if c == ex else 1
    ex = c
    best = max(best, cnt)      # ⭐ max를 매번 갱신하면 루프 밖 처리가 필요 없다
print(best)
```

### 주의할 점

- ⚠️⭐ **루프가 끝난 뒤 마지막 묶음을 넣었는지** 항상 확인. 이 문제 오답의 90%가 여기다.
- ⚠️⭐ 마지막 글자를 **루프 안에서 `if`로 가로채지 말 것.** 가로채면 **같은지 비교를 건너뛴다.**
- ⚠️⭐ 테스트는 **마지막 글자가 앞과 다른 입력**으로 할 것 (`abcd`, `abccdabba`).
  `aabb`처럼 **끝이 겹치는 입력만 보면 틀린 코드도 통과**한다. (ch8의 "직사각형으로 테스트"와 같은 교훈)
- ⚠️ 새 묶음을 시작할 땐 **`cnt = 1`** 이다. `cnt = 0`으로 두면 **전부 1씩 적게** 센다.
  (지금 보고 있는 글자가 **이미 첫 번째**이기 때문)
- ⚠️ `ex = c` 와 `cnt = 1` 은 **반드시 같이** 간다. 하나만 바꾸면 조용히 틀린다.
- ⚠️ `f"{ex}{cnt}"` 는 숫자를 알아서 문자로 바꿔 주지만, `ex + cnt` 는 **TypeError**다.
  `+` 로 이을 땐 **`ex + str(cnt)`**.
- ⚠️ 변수 이름으로 **`sum`, `list`, `str`, `max`, `min`** 금지 — 내장 함수가 가려진다.
- ⚠️ 한 줄로 이어 출력하려면 `print(i, end="")` 보다 **`print(''.join(arr))`** 가 안전하다.
  (`end=""`만 쓰면 **마지막 줄바꿈이 없어** 채점에서 걸릴 수 있다.)
- ⚠️ `A`가 **빈 문자열이면 `A[0]`에서 IndexError**. 코드트리는 보통 1글자 이상이지만,
  `if not A: print(0)` 로 막아 두는 습관은 둘 만하다.

## 3. 부분 문자열 찾기 — `in` / `find()` / `count()`

### 핵심 요약

- ⭐⭐ **문자열에서 `in`은 "부분 문자열이 들어 있나"** 를 묻는다. 한 글자가 아니어도 된다.

  ```python
  s = 'appleabanana'
  print('ab' in s)       # True
  print('xy' in s)       # False
  ```

- ⭐ 직접 짠 **슬라이싱 반복문과 결과가 완전히 같다.** 생각하는 방식도 같다 —
  왼쪽부터 "여기서 시작하면 `ab`인가?"를 차례로 보는 것.

  ```python
  # 아래 둘은 결과가 같다
  exists = False
  for i in range(len(s) - 1):
      if s[i:i+2] == 'ab':
          exists = True

  exists = 'ab' in s          # ⭐ 한 줄
  ```

- ⚠️ 다만 **"똑같이 동작"하지는 않는다.** `in`은 **C로 구현**돼 있고,
  안 맞으면 **한 칸이 아니라 여러 칸을 건너뛰며**, **새 문자열을 만들지 않는다.**

  | 20만 글자에서 `'ab'` 찾기 | 시간 |
  | --- | --- |
  | 슬라이싱 반복문 | `7.607 ms` |
  | `'ab' in s` | `0.110 ms` (**69배 빠름**) |

- ⭐ 반복문이 느린 진짜 이유는 비교가 아니라 **`s[i:i+2]`가 매 바퀴 새 문자열을 만드는 것**이다.
  20만 바퀴면 두 글자짜리 쓰레기 문자열을 **20만 개** 만든다.

### 3형제 — 있나 / 어디 / 몇 개

| 쓰는 법 | 묻는 것 | `'appleabanana'` 기준 |
| --- | --- | --- |
| `'ab' in s` | **있나?** | `True` |
| `s.find('ab')` | **어디?** (첫 위치) | `5` |
| `s.count('ab')` | **몇 개?** | `1` |

```python
s = 'appleabanana'
print('ab' in s)        # True
print(s.find('ab'))     # 5    ← 없으면 -1
print(s.count('ab'))    # 1
print(s.index('ab'))    # 5    ← 없으면 ValueError (에러로 멈춤)
```

- ⭐ **없을 때가 중요하다.** `find`는 **`-1`**, `index`는 **에러**. 코딩테스트에서는 **`find`가 안전**하다.
- ⚠️ `find`가 `-1`을 돌려준다는 건 **`if s.find('ab'):` 가 위험**하다는 뜻이다. `-1`은 **참**이다.
  반드시 **`if s.find('ab') != -1:`** 라고 적는다. ("있나?"만 물을 거면 그냥 `in`을 쓴다.)
- ⚠️ `count`는 **겹치는 건 안 센다.** `'aaa'.count('aa')` → **`2`가 아니라 `1`**.

### `find()` 의 인수 3개 — 찾을 것 / 어디서부터 / 어디까지

```
s.find( 찾을 문자열 , 어디서부터 , 어디까지 )
            필수         선택        선택
            sub         start        end
```

아래 설명은 전부 **`s = 'banana'`** 기준이다.

```
 b  a  n  a  n  a
 0  1  2  3  4  5
```

**① 인수 하나 — 첫 번째 위치**

```python
'banana'.find('a')      # 1    ← 가장 앞선 위치
'banana'.find('na')     # 2    ← 여러 글자도 된다
'banana'.find('z')      # -1   ← 없으면 -1 (에러가 아니다)
```

**② 두 번째 인수 `start` — "여기서부터 찾아라"**

```python
'banana'.find('a')       # 1
'banana'.find('a', 2)    # 3    ← 2번부터 보니 1은 건너뛴다
'banana'.find('a', 4)    # 5
'banana'.find('a', 6)    # -1   ← 범위를 넘어가도 에러가 아니라 -1
```

- ⭐ **개수 세기·위치 모으기에서 `pos`를 넘기던 게 바로 이 인수**다.

**③ 세 번째 인수 `end` — "여기까지만 보라"** (슬라이싱처럼 **end는 불포함**)

```python
'banana'.find('a', 0, 2)     # 1    ← 'ba' 구간 안
'banana'.find('a', 0, 1)     # -1   ← 'b' 뿐이라 없음
'banana'.find('na', 2, 4)    # 2    ← 'na' 가 통째로 들어감
'banana'.find('na', 2, 3)    # -1   ⚠️ 'n' 만 들어가 잘렸다
```

- ⚠️ 구간을 자르는 것이므로, 찾는 문자열이 **통째로** 구간 안에 들어가야 한다.

### ⭐⭐ 가장 중요한 것 — 반환값은 언제나 "원본 기준"

```python
s = 'banana'
s.find('a', 3)         # 3   ← 원본에서 센 위치  ⭐
s[3:].find('a')        # 0   ← 잘라낸 조각에서 센 위치  ⚠️
s[3:].find('a') + 3    # 3   ← 직접 더해 줘야 맞는다
```

- 구간을 아무리 좁혀도 **위치는 원본에서 센 값**이다.
- ⭐ 그래서 **`s[3:].find(...)` 보다 `s.find(..., 3)` 이 낫다.**
  ① 위치를 보정할 필요가 없고, ② **새 문자열을 만들지 않는다.**

### 같이 알아 둘 것

```python
'banana'.find('a', -3)       # 3    ← 음수 인덱스도 된다 (뒤에서 3번째부터)
'banana'.rfind('a')          # 5    ← 뒤에서부터 찾기
'banana'.rfind('a', 0, 4)    # 3
'banana'.find('')            # 0    ← 빈 문자열은 start 를 그대로 돌려준다
```

- ⚠️ **`rfind` 는 찾는 방향만 반대**고, **위치는 여전히 왼쪽에서 센 값**이다. 거꾸로 센 값이 아니다.
- ⚠️ 인수는 **문자열만** 받는다.

  ```python
  'banana'.find(97)     # TypeError: find() argument 1 must be str, not int
  'banana'.find()       # TypeError: find expected at least 1 argument, got 0
  ```

- ⭐⭐ **`index`, `rfind`, `rindex`, `count` 도 인수 구조가 똑같다** — `(찾을 것, start, end)`.
  하나만 익히면 전부 쓸 수 있다.

  ```python
  'banana'.count('a')          # 3
  'banana'.count('a', 2)       # 2    ← 2번부터 세기
  'banana'.count('a', 2, 4)    # 1
  ```

### 예시 코드

**① 반복문으로 직접 — 일반화한 올바른 형태 ⭐**

```python
s = input()
t = 'ab'

exists = False
for i in range(len(s) - len(t) + 1):        # ⭐⭐ 범위는 len(s) - len(t) + 1
    if s[i:i+len(t)] == t:
        exists = True
        break                               # ⭐ 찾았으면 더 볼 이유가 없다
print(exists)
```

- ⚠️⭐ **`range(len(s) - 1)` 은 "2글자를 찾을 때"만 맞는 식**이다.
  `len(s) - 2 + 1 = len(s) - 1` 이라 우연히 맞아떨어진 것.
  3글자를 찾는데 그대로 쓰면 **맨 끝에서 짧게 잘린 조각과 비교**하게 된다.
- ⚠️ **`break`를 빼먹지 말 것.** 없으면 첫 글자에서 찾아도 **끝까지 전부** 돈다.

**② 위치를 전부 모으기 — `find`의 두 번째 인자**

```python
s = 'appleabanaba'           # ab 가 두 번 (5, 9)
pos = s.find('ab')
while pos != -1:
    print(pos)               # 5, 9
    pos = s.find('ab', pos + 1)    # ⭐ pos+1 부터 다시 찾는다
```

- `s.find('ab', 시작위치)` — **어디서부터 찾을지**를 정할 수 있다.
- ⚠️ `pos + 1`을 빼먹으면 **같은 자리를 영원히** 찾아 무한 루프.

**③ 앞/뒤만 확인 — `startswith()` / `endswith()`**

```python
'apple.py'.endswith('.py')      # True
'apple'.startswith('ap')        # True
'apple'[:2] == 'ap'             # True   ← 같은 뜻이지만 길이 실수가 생기기 쉽다
```

- ⭐ **앞뒤를 볼 땐 슬라이싱보다 이쪽이 안전**하다. 길이를 셀 필요가 없다.

**④ 뒤에서부터 찾기 — `rfind()`**

```python
'appleabanana'.find('a')     # 0   ← 맨 앞
'appleabanana'.rfind('a')    # 11  ← 맨 뒤
```

### 위치까지 구하기 — 세 가지 방법 비교

**① 반복문으로 직접 — 글자 단위 비교 (코드트리 방식)**

```python
s = 'appleabanana'
length = len(s)
start_idx = -1                              # ⭐ "못 찾았다"를 -1로 미리 정해 둔다

for i in range(length - 1):                 # ⚠️ i + 1 을 보니까 끝을 하나 남긴다
    if s[i] == 'a' and s[i + 1] == 'b':
        start_idx = i
        break                               # ⭐ 가장 앞선 위치니까 즉시 멈춘다

print(start_idx)                            # 5
```

- `s[i:i+2] == 'ab'` 대신 **`s[i] == 'a' and s[i+1] == 'b'`** 로 글자를 하나씩 비교한 형태다.
  **새 문자열을 안 만들어서** 슬라이싱보다 낫다. 대신 **찾을 글자 수만큼 조건이 길어진다.**
- ⭐⭐ **`start_idx = -1` 로 시작하는 게 핵심 패턴**이다.
  찾으면 덮어쓰고, 끝까지 못 찾으면 **-1이 그대로 남아** 답이 된다.
  → `find()` 가 없을 때 `-1`을 주는 것도 **정확히 같은 발상**이다.
- ⚠️⭐ **`break`가 "가장 앞선 위치"를 보장한다.** 빼면 **마지막 위치**가 남는다.
  (앞에서 쓴 `exists = True` 는 어차피 True라 break가 성능 문제였지만, **여기선 답이 틀린다.**)
- ⚠️ `range(length - 1)` 인 이유는 **`s[i+1]` 을 보기 때문**이다. `range(length)` 로 두면
  마지막 바퀴에서 `s[length]` 를 읽어 **IndexError**.

**② `in` 으로 확인하고 `index` 로 위치 구하기**

```python
s = 'appleabanana'

if 'ab' in s:
    print(s.index('ab'))     # 5
else:
    print(-1)
```

- `index` 는 **없으면 ValueError로 멈춘다.** 그래서 **반드시 `in` 과 짝**으로 써야 한다.

  ```python
  'appleabanana'.index('bbb')   # ValueError: substring not found
  ```

- ⚠️ 대신 **문자열을 두 번 훑는다.** (`in` 에서 한 번, `index` 에서 또 한 번)

**③ `find` 하나로 끝내기 ⭐ (가장 권장)**

```python
s = 'appleabanana'
print(s.find('ab'))      # 5
print(s.find('bob'))     # -1   ← 에러 없이 -1
```

- ⭐ **`find` 는 "확인 + 위치"를 한 번에** 한다. ①의 `start_idx = -1` 패턴이 **이미 내장된 함수**다.

| 구분 | 없을 때 | 훑는 횟수 | 줄 수 |
| --- | --- | --- | --- |
| 반복문 | `-1` (내가 만듦) | 1번 | 6줄 |
| `in` + `index` | `-1` (내가 만듦) | **2번** | 4줄 |
| **`find`** | **`-1`** (자동) | **1번** | **1줄** ⭐ |

```
200만 글자, 찾는 문자열이 맨 뒤에 있을 때
  in + index :  0.763 ms
  find       :  0.363 ms     ← 2.1배
```

- **결론: 위치가 필요하면 `find`, 있는지만 알면 `in`.** `index` 는 `in` 없이 혼자 쓰지 않는다.

### 몇 번 나왔나 — 직접 세기 (`index` / `find` 반복)

- ⭐ **열쇠는 두 번째 인자(시작 위치)다.** `s.index(t, pos)`, `s.find(t, pos)` —
  **찾은 자리 다음부터 다시 찾기**를 반복하면 개수가 나온다. 위치를 모으는 것과 같은 틀이다.

**① `index` 로 세기 — `try/except` 가 필수**

```python
s = 'appleabanaba'
t = 'ab'

cnt = 0
pos = 0
while True:
    try:
        pos = s.index(t, pos)     # ⭐ pos 부터 찾는다
    except ValueError:
        break                     # ⭐ 더 없으면 에러가 난다 = 끝났다는 신호
    cnt += 1
    pos += len(t)                 # 찾은 것 뒤로 건너뛴다

print(cnt)        # 2
```

- `index` 는 없을 때 **에러를 내므로**, "끝"을 **`except ValueError` 로 잡아야** 한다.
- ⚠️ `pos += len(t)` 를 빼먹으면 **같은 자리를 계속 찾아 무한 루프**다.

**② `in` 으로 확인하며 세기 — 되지만 비효율**

```python
cnt = 0
pos = 0
while t in s[pos:]:               # ⚠️ 바퀴마다 s[pos:] 새 문자열이 만들어진다
    pos = s.index(t, pos) + len(t)
    cnt += 1
```

- `try` 를 피할 수 있지만, **자르기 + 두 번 훑기**가 겹쳐서 가장 느리다.

**③ `find` 로 세기 ⭐ (직접 짠다면 이 형태)**

```python
cnt = 0
pos = 0
while True:
    pos = s.find(t, pos)
    if pos == -1:                 # ⭐ 에러 대신 -1 — try 가 필요 없다
        break
    cnt += 1
    pos += len(t)
```

**④ 실전 — 한 줄**

```python
print(s.count(t))     # 2
```

### ⭐ 직접 세는 게 꼭 필요한 경우 — 겹치는 것 세기

- ⚠️⭐ **`count()` 는 겹치는 걸 안 센다.** 한 번 세면 **그 뒤로 건너뛰기** 때문이다.
- 전진 폭을 **`len(t)` 대신 `1`** 로 바꾸면 겹치는 것까지 센다.

```python
cnt = 0
pos = 0
while True:
    pos = s.find(t, pos)
    if pos == -1:
        break
    cnt += 1
    pos += 1          # ⭐⭐ 1칸만 전진 → 겹침도 센다
```

| 입력 | 찾는 것 | `count()` | 1칸씩 전진 |
| --- | --- | --- | --- |
| `'aaa'` | `'aa'` | `1` | **`2`** |
| `'aaaa'` | `'aa'` | `2` | **`3`** |
| `'banana'` | `'ana'` | `1` | **`2`** |

- `'banana'` 의 `ana` 는 **인덱스 1과 3에 겹쳐서** 두 번 있다.
  `count()` 는 1에서 세고 **4로 건너뛰어** 3을 놓친다.
- ⭐ **"겹쳐도 모두 세라"는 문제가 나오면 `count()` 를 쓰면 안 된다.** 직접 짜야 한다.

### ⚠️ `in`은 자료형마다 뜻이 다르다

```python
'ab' in 'appleabanana'      # True   ← 문자열: "부분 문자열"
'ab' in ['ab', 'cd']        # True   ← 리스트: "원소 그 자체"
'a'  in ['ab', 'cd']        # False  ⚠️ 'ab' 안을 들여다보지 않는다!
```

- ⭐⭐ **문자열의 `in`은 "조각", 리스트의 `in`은 "통째로"** — 가장 헷갈리는 지점이다.
- 리스트에서 부분 일치를 보고 싶으면 **원소 하나하나에** `in`을 쓴다.

  ```python
  arr = ['ab', 'cd']
  print(any('a' in w for w in arr))     # True
  ```

### 주의할 점

- ⚠️⭐ 반복문 범위는 **`len(s) - len(t) + 1`**. `len(s) - 1` 은 **2글자 전용**이다.
- ⚠️⭐ `find` 의 반환값은 **언제나 원본 기준**이다. `s[k:].find(...)` 를 썼으면 **`+ k` 를 더해야** 한다.
- ⚠️ 세 번째 인수 `end` 는 **불포함** — 찾는 문자열이 **통째로** 구간에 들어가야 한다.
- ⚠️ `rfind` 는 **방향만 반대**, 위치는 **왼쪽에서 센 값**이다.
- ⚠️⭐ `find`는 없을 때 **`-1`**, `index`는 **ValueError**. `-1`은 **참**이라 `if s.find(...)` 는 틀린다.
- ⚠️⭐ `count`는 **겹침을 안 센다** — `'aaa'.count('aa')` 는 `1`, `'banana'.count('ana')` 는 `1`.
  겹치는 것까지 세려면 **`find` 로 직접 돌면서 `pos += 1`** (`len(t)` 가 아니라 1칸).
- ⚠️ 반복해서 찾을 땐 **`pos` 를 반드시 전진**시킨다 — 안 그러면 무한 루프.
- ⚠️ `in`은 **대소문자를 구분**한다. 무시하려면 **양쪽 다** `.lower()` (ch8의 비교와 같은 규칙).

  ```python
  'AB' in 'appleab'              # False
  'ab' in 'appleAB'.lower()      # True
  ```

- ⚠️ 리스트의 `in`은 **원소 전체 일치**다. 문자열처럼 부분 일치로 착각하지 말 것.
- ⚠️ 찾을 문자열이 **빈 문자열이면** `'' in s` 는 **항상 True** (반복문 버전과 유일하게 갈라지는 지점).
- ⚠️⭐ **`index` 는 `in` 없이 혼자 쓰지 않는다.** 없으면 ValueError로 프로그램이 멈춘다.
  (그래도 `find` 한 줄이 더 낫다 — `in` + `index` 는 **두 번 훑는다**.)
- ⚠️⭐ 위치를 찾을 땐 **`break` 가 답을 바꾼다.** 빼면 **가장 앞**이 아니라 **가장 뒤**가 남는다.
- ⚠️ `s[i+1]` 을 보는 반복문은 범위가 **`range(len(s) - 1)`** — `range(len(s))` 면 IndexError.
- ⭐ 실전 결론 — **있나? `in` / 어디? `find` / 몇 개? `count`.** 직접 반복문 짜지 않는다.

## 4. 문자열의 글자 바꾸기·제거하기 — `list()` 로 풀었다가 `join()` 으로 묶기

### 핵심 요약

- ⚠️⭐ **문자열은 한 글자만 바꿔치기할 수 없다.** 수정이 불가능(immutable)하기 때문이다.

  ```python
  s = 'baaana'
  s[2] = 'n'      # TypeError: 'str' object does not support item assignment
  ```

- ⭐⭐ 그래서 **"풀었다가 → 고치고 → 다시 묶는다"** 는 3단계를 쓴다.

  ```
  'baaana'  --list()-->  ['b','a','a','a','n','a']  --고치고-->  --''.join()-->  'banana'
   문자열                      리스트 (수정 가능!)                              문자열
  ```

  ```python
  s = 'baaana'
  arr = list(s)              # ① 한 글자씩 리스트로 푼다
  arr[2] = 'n'               # ② 리스트는 수정이 된다  ⭐
  s = ''.join(arr)           # ③ 다시 문자열로 묶는다
  print(s)                   # banana
  ```

- ⭐ **`list(s)` 는 문자열을 한 글자씩 쪼갠다.** `split()` 처럼 구분자가 필요 없다.

  ```python
  list('baaana')      # ['b', 'a', 'a', 'a', 'n', 'a']
  ```

- ⭐ **`'구분자'.join(리스트)` 는 그 반대다.** 점을 찍는 쪽이 **구분자**라는 게 헷갈리는 지점.

  ```python
  ''.join(['b','a','n'])      # 'ban'      ← 빈 문자열 = 그냥 붙이기
  ' '.join(['b','a','n'])     # 'b a n'    ← 공백으로 끼워 넣기
  ```

### 더 짧은 방법 — 슬라이싱으로 이어 붙이기 ⭐

```python
s = 'baaana'
s = s[:2] + 'n' + s[3:]     # 'banana'
#   └앞부분┘  └새것┘ └뒷부분┘
```

- **한 글자만** 바꿀 거면 이쪽이 더 짧다. 리스트를 만들 필요가 없다.
- ⚠️ **바꿀 위치 `k` 를 건너뛰는 게 핵심** — `s[:k] + 새글자 + s[k+1:]`.
  `s[k:]` 라고 쓰면 **원래 글자가 그대로 남아** 길이가 하나 늘어난다.

| 상황 | 추천 |
| --- | --- |
| 한 글자만 바꾼다 | **슬라이싱** `s[:k] + c + s[k+1:]` |
| 여러 글자를 돌면서 바꾼다 | **`list()` → 수정 → `join()`** ⭐ |
| 특정 **글자**를 전부 바꾼다 | **`replace()`** |

### ⚠️ `replace()` 는 "위치"가 아니라 "값"으로 바꾼다

```python
'baaana'.replace('a', 'n')       # 'bnnnnn'   ← a 를 전부
'baaana'.replace('a', 'n', 1)    # 'bnaana'   ← 앞에서 1개만  ⭐
```

- ⭐ 세 번째 인수는 **"몇 개까지 바꿀지"** 다. (`find` 의 세 번째 인수와는 뜻이 다르다)
- ⚠️ **"3번째 글자를 바꿔라"에는 쓸 수 없다.** `replace` 는 위치를 모른다.
  위치로 바꿀 땐 **슬라이싱이나 `list()`** 를 쓴다.

### ⭐⭐ 더 중요한 쓸모 — 반복문에서 문자열을 만들 때

- 2번(문자열 압축)에서 `result += ...` 로 이어 붙였는데, 사실 **`list` + `join` 이 더 좋다.**
- 문자열은 수정이 안 되므로 **`+=` 는 매번 "새 문자열을 통째로 다시 만든다".**
  리스트의 `append` 는 **뒤에 끼워 넣기만** 하므로 훨씬 싸다.

```python
# △ 글자가 많아지면 느려진다
result = ''
for c in s:
    result += c.upper()

# ⭐ 권장 — 모았다가 마지막에 한 번 묶는다
arr = []
for c in s:
    arr.append(c.upper())
result = ''.join(arr)
```

```
10만 글자를 만들 때
  += 누적     :  2.79 ms
  list + join :  1.26 ms     ← 2.2배
```

- ⭐ **"조각을 모을 땐 리스트, 마지막에 `join`"** — 출력에서 쓰던 `''.join(row)` 와 같은 습관이다.

### 글자 **제거**하기 — 바꾸기와 같은 틀, 가운데만 비우면 된다

- ⭐⭐ **제거 = 바꾸기에서 "새 글자"를 빼는 것**이다. 두 방법이 그대로 대응된다.

  ```python
  s = s[:k] + c + s[k+1:]      # k번째를 c 로 바꾸기
  s = s[:k]     + s[k+1:]      # k번째를 제거       ⭐ 가운데만 없앴다
  ```

**① 슬라이싱으로 양쪽만 살리기**

```python
s = 'baknana'
s = s[:2] + s[3:]        # 'banana'   ← 2번('k') 제거
print(s)
```

```
 b  a  k  n  a  n  a
 0  1  2  3  4  5  6
└s[:2]┘  └── s[3:] ──┘     ⭐ 2번을 건너뛴다
```

- ⚠️⭐ **`s[:2] + s[2:]` 라고 쓰면 아무것도 안 지워진다.** 원본 그대로 `'baknana'` 가 나온다.
  지울 자리를 **건너뛰어야** 하므로 뒤쪽은 반드시 **`s[k+1:]`**.

**② `list` 로 풀어서 `pop()` 으로 빼기**

```python
s = 'baknana'
arr = list(s)
arr.pop(2)               # ⭐ 2번 원소를 빼낸다
s = ''.join(arr)
print(s)                 # banana
```

- ⭐ `pop(i)` 는 **뺀 값을 돌려주기도 한다.** 무엇이 빠졌는지 알아야 할 때 쓸모 있다.

  ```python
  arr = list('baknana')
  x = arr.pop(2)
  print(x)               # 'k'   ← 빠진 글자
  print(arr)             # ['b','a','n','a','n','a']
  ```

- ⚠️ 리스트는 **원본이 직접 바뀐다.** `arr = arr.pop(2)` 라고 쓰면 **`arr` 에 `'k'` 가 들어가** 망가진다.
  (문자열 함수와 반대 — ch8의 "문자열은 새로 돌려주고 list는 자기를 고친다")

### 지우는 방법 4가지 — 무엇으로 지우느냐가 다르다

| 방법 | 무엇으로 | 반환값 | 예 |
| --- | --- | --- | --- |
| `s[:k] + s[k+1:]` | **위치** | 새 문자열 | 문자열에 바로 쓸 수 있다 ⭐ |
| `arr.pop(k)` | **위치** | **뺀 값** | `'k'` |
| `del arr[k]` | **위치** | 없음 | 값이 필요 없을 때 |
| `arr.remove(c)` | **값** | 없음 | ⚠️ **맨 앞 1개만** |

```python
a = list('abcabc')
a.remove('b')        # ['a','c','a','b','c']   ⚠️ 뒤의 b 는 남는다
```

- ⭐ **위치로 지울지, 값으로 지울지**를 먼저 정하면 고르기 쉽다.
- `del` 은 **구간째** 지울 수 있다. 슬라이싱과 같은 일을 한다.

  ```python
  t = 'abcdef'
  print(t[:1] + t[4:])              # 'aef'
  a = list(t); del a[1:4]           # 같은 결과
  print(''.join(a))                 # 'aef'
  ```

### 값으로 지우려면 `replace(c, '')` 가 가장 쉽다 ⭐

```python
'baknana'.replace('k', '')      # 'banana'   ← k 를 전부 지운다
'baaana'.replace('a', '')       # 'bn'
'baaana'.replace('a', '', 1)    # 'baana'    ← 앞에서 1개만
```

- ⭐ **"바꿀 글자를 빈 문자열로"** = 지우기. `list` 도 `pop` 도 필요 없다.
- ⚠️ 역시 **위치는 모른다.** "3번째 글자를 지워라"에는 못 쓴다.

### 주의할 점

- ⚠️⭐ 제거할 때 뒤쪽은 **`s[k+1:]`** — `s[k:]` 는 **아무것도 안 지운다.**
- ⚠️⭐ `arr.pop(k)` 는 **원본을 고치고 뺀 값을 돌려준다.** `arr = arr.pop(k)` 로 담으면 안 된다.
- ⚠️ `remove` 는 **값으로, 맨 앞 1개만** 지운다. 전부 지우려면 `replace` 나 컴프리헨션.

  ```python
  ''.join([c for c in 'baaana' if c != 'a'])    # 'bn'
  ```

- ⚠️ 없는 걸 지우면 에러다. **`pop` 은 IndexError, `remove` 는 ValueError.**

  ```python
  list('abc').pop(9)        # IndexError: pop index out of range
  list('abc').remove('z')   # ValueError: list.remove(x): x not in list
  []. pop()                 # IndexError: pop from empty list
  ```

  → 슬라이싱은 **범위를 넘어도 에러가 안 난다.** 그래서 더 안전하다.
- ⚠️⭐ **반복문을 돌면서 지우면 안 된다.** 뒤 원소들이 앞으로 당겨져 **한 칸씩 건너뛴다.**
  → **남길 것을 모으는 쪽**으로 뒤집어 생각한다. (위의 컴프리헨션)
- ⚠️ `del s[2]` 는 문자열에 못 쓴다 — **AttributeError**. 역시 수정 불가라서.

### 예시 코드

**① 입력받은 문자열의 k번째 글자를 바꾸기**

```python
s = input()
k = int(input())
c = input()

arr = list(s)
arr[k] = c                  # ⚠️ 문제가 1번부터 센다면 arr[k-1]
print(''.join(arr))
```

- ⚠️⭐ **문제의 번호가 0부터인지 1부터인지** 반드시 확인한다. 1부터면 **`k - 1`**.

**② 조건에 맞는 글자만 바꾸기 — 리스트가 편한 경우**

```python
s = input()
arr = list(s)
for i in range(len(arr)):
    if arr[i] == 'a':
        arr[i] = arr[i].upper()
print(''.join(arr))
```

**③ 뒤집기 — `list` 없이도 된다**

```python
s = 'banana'
print(s[::-1])                 # 'ananab'   ⭐ 가장 짧다
print(''.join(reversed(s)))    # 'ananab'
arr = list(s); arr.reverse()
print(''.join(arr))            # 'ananab'
```

**④ 정렬 — 이땐 `list` 가 필요하다**

```python
s = 'banana'
print(''.join(sorted(s)))      # 'aaabnn'   ⭐ sorted 는 리스트를 돌려준다
```

- `sorted(s)` 는 문자열을 넣어도 **리스트**를 돌려주므로, **`join` 으로 다시 묶어야** 한다.

### 주의할 점

- ⚠️⭐ `s[k] = c` 는 **TypeError**. 문자열은 수정 불가 — 이건 `.upper()` 때와 같은 성질이다. (ch8)
- ⚠️⭐ **`''.join(arr)` 의 결과를 다시 담아야** 한다. `''.join(arr)` 만 쓰면 사라진다.
- ⚠️⭐ **`join` 은 문자열 리스트만** 받는다. 숫자가 섞이면 TypeError.

  ```python
  ''.join(['a', 1, 'b'])             # TypeError: sequence item 1: expected str instance
  ''.join(map(str, ['a', 1, 'b']))   # 'a1b'   ⭐ str 로 바꿔서 넣는다
  ''.join([str(x) for x in [1,2,3]]) # '123'
  ```

- ⚠️ **점을 찍는 쪽이 구분자**다. `arr.join('')` 이 아니라 **`''.join(arr)`**.
- ⚠️ `list(s)` 와 `s.split()` 은 다르다. **`list` 는 한 글자씩**, **`split` 은 공백으로 덩어리째**.

  ```python
  list('a b')       # ['a', ' ', 'b']   ← 공백도 한 글자
  'a b'.split()     # ['a', 'b']
  ```

- ⚠️ 슬라이싱으로 바꿀 땐 **`s[k+1:]`** — `s[k:]` 로 쓰면 원래 글자가 남는다.
- ⚠️ `replace` 는 **위치를 모른다.** "n번째 글자"에는 못 쓴다.
- ⚠️ 인덱스가 **0부터인지 1부터인지** 문제마다 확인. 1부터면 `k - 1`.

## 5. 문자열 계속 지우기 — 반복해서 지우기 (Hard)

> [코드트리 「문자열 계속 지우기」](https://www.codetree.ai/trails/complete/curated-cards/) 유형.
> 3번(찾기)과 4번(지우기)을 **합치면 그대로 풀린다.**

### 문제 요약

- 문자열 `A` 에서 **가장 앞에 등장하는** `B` 를 찾아 지운다.
- 지우고 나면 **양쪽이 다시 붙으므로**, 새로 생긴 `B` 도 또 지운다.
- `B` 가 더 이상 없을 때까지 반복한 뒤 남은 문자열을 출력한다.

```
A = baabba,  B = ab
  baabba  →  baba  →  ba        (답: ba)
     └ab┘      └ab┘
```

### 핵심 요약

- ⭐⭐ **"없어질 때까지 반복"은 `while` 이다.** 몇 번 반복할지 모르니 `for` 가 아니다.

  ```
  while  B가 A 안에 있는 동안:
      가장 앞의 B 하나를 지운다
  ```

- ⭐ 두 조각을 3·4번에서 이미 배웠다. **그대로 끼워 넣으면 끝이다.**
  - "있나?" → **`B in A`** (3번)
  - "가장 앞 하나만 지우기" → **`A.replace(B, '', 1)`** (4번)
- ⚠️⭐⭐ **세 번째 인수 `1` 을 빼먹으면 틀린다.** 이 문제의 핵심 함정이다. (아래에서 자세히)

### 예시 코드

**① 정답 ⭐ (가장 짧다)**

```python
A = input()
B = input()

while B in A:
    A = A.replace(B, '', 1)     # ⭐ 1 = "가장 앞 하나만"

print(A)
```

- `in` 으로 확인하고, `replace(..., 1)` 로 **맨 앞 하나만** 지운다. 그게 문제 설명 그대로다.
- ⚠️ **`A = ` 로 다시 담아야** 한다. 문자열은 수정이 안 된다. (4번)

**② `find` + 슬라이싱 — 문제 설명을 그대로 옮긴 형태**

```python
A = input()
B = input()

while True:
    pos = A.find(B)
    if pos == -1:               # 더 없으면 끝
        break
    A = A[:pos] + A[pos + len(B):]      # ⭐ 찾은 구간만 건너뛴다

print(A)
```

- ⭐ **`pos + len(B)`** 가 핵심이다. `B` 의 길이만큼 건너뛰어야 한다.
  4번에서 한 글자를 지울 때 `s[k+1:]` 이었던 것의 **일반형**이다.
- 이 형태는 `replace` 를 몰라도 풀리고, **무엇이 지워지는지 눈에 보인다.**

**③ 스택 — 한 번만 훑고 끝내기 (고급)**

```python
A = input()
B = input()
n = len(B)

st = []
for c in A:
    st.append(c)
    if len(st) >= n and ''.join(st[-n:]) == B:   # 뒤쪽 n글자가 B면
        del st[-n:]                              # 통째로 뺀다

print(''.join(st))
```

- ①②는 지울 때마다 문자열을 **처음부터 다시 훑지만**, 스택은 **한 번만** 훑는다.
- 이 문제는 길이가 **100 이하**라 ①로 충분하다. 다만 **"지우면 양쪽이 붙는다"** 류 문제의
  **정석 풀이**라서 알아 두면 나중에 길이가 10만쯤 될 때 쓴다.
- 무작위 3만 건으로 ①②③이 **모두 같은 답**을 내는 것을 확인했다.

### ⚠️⭐⭐ 가장 큰 함정 — `replace(B, '')` 는 틀린다

- `replace` 는 인수 `1` 이 없으면 **찾은 것을 전부 한꺼번에** 지운다.
- 그런데 문제는 **"가장 앞 하나씩"** 지우라고 했다. 하나를 지우면 **양쪽이 붙으면서
  판이 바뀌는데**, 전부 지우면 그 변화를 **무시**해 버린다.

**반례: `A = 'abbabababb'`, `B = 'bab'`**

```
[정답] 가장 앞 것 하나씩
  abbabababb  → 2번 제거 →  abababb
  abababb     → 1번 제거 →  aabb
  최종: aabb          ✅

[틀림] replace 전부
  abbabababb  → 한 번에 2개 제거 →  abab
  abab        → 제거 →  a
  최종: a             ❌
```

- 첫 줄에서 `'abbabababb'.count('bab')` 는 **2** 다. `replace` 는 이 둘을 **동시에** 지운다.
- 하지만 정답은 **앞의 하나만** 지우고, 그때 생긴 새 모양에서 **다시** 찾아야 한다.
- ⚠️ `'baabba'`, `'ab'` 같은 **예제 입력으로는 둘 다 `ba` 가 나와서 통과**한다.
  **예제만 맞춰 보고 제출하면 틀리는** 전형적인 문제다. (2번의 `aabb` 교훈과 같다)

### 주의할 점

- ⚠️⭐⭐ **`replace(B, '', 1)` 의 `1` 을 빼먹지 말 것.** 예제는 통과하고 채점에서 틀린다.
- ⚠️⭐ **`A = A.replace(...)` 로 다시 담기.** 문자열은 수정 불가다.
- ⚠️⭐ `find` 로 풀 땐 뒤쪽이 **`A[pos + len(B):]`** — `A[pos+1:]` 이 아니다.
  (한 글자 지우기만 연습하면 `+1` 이라고 쓰기 쉽다.)
- ⚠️ `while B in A:` 안에서 **A를 줄이지 않으면 무한 루프**다. 반드시 `A` 가 짧아져야 한다.
- ⚠️ 반복 횟수를 모르니 **`for` 가 아니라 `while`**. `for _ in range(len(A))` 로 두면 모자랄 수 있다.
- ⚠️ 다 지워져서 **빈 문자열이 남을 수 있다.** `print(A)` 는 **빈 줄**을 출력한다 — 그게 정답이다.
  (`if A: print(A)` 처럼 막으면 오히려 틀린다.)
- ⚠️ `B` 가 `A` 에 처음부터 없으면 **`while` 을 한 번도 안 돌고** `A` 를 그대로 출력한다. 정상이다.

## 6. 아스키 코드와 글자 판별 — `chr()` / `ord()` / `isalpha()` / `isdigit()`

> ch8의 `.upper()` 끝에서 잠깐 봤던 내용의 **본편**이다. ([ch8 노트](ch8_2차원배열.md))

### 핵심 요약

- ⭐⭐ 컴퓨터는 글자를 **번호로** 저장한다. 그 번호가 **아스키 코드**다.
  - **`ord(글자)` → 번호** ("order", 순번)
  - **`chr(번호)` → 글자** ("character", 글자)
  - 이름이 헷갈리면 **"`chr` 는 글자(char)를 만든다"** 로 외운다.

  ```python
  ord('A')      # 65
  chr(65)       # 'A'
  chr(66)       # 'B'      ⭐ 번호가 이어지면 글자도 이어진다
  ```

- ⭐⭐ **외울 번호는 세 개뿐**이다. 나머지는 거기서 센다.

  ```
  '0' = 48 ... '9' =  57      (숫자 10개)
  'A' = 65 ... 'Z' =  90      (대문자 26개)
  'a' = 97 ... 'z' = 122      (소문자 26개)
                 └ 대↔소 차이는 항상 32 ┘
  ```

- ⭐ 사실 **번호를 외울 필요도 없다.** `ord('a')` 라고 적으면 되기 때문이다.

  ```python
  ord('c') - ord('a')      # 2    ⭐ 알파벳을 0~25 번호로
  chr(ord('a') + 2)        # 'c'  ⭐ 번호를 다시 글자로
  ```

### 글자끼리 직접 비교하기 ⭐

- ⭐⭐ **글자는 `<`, `>` 로 바로 비교된다.** 속으로 아스키 번호를 비교하기 때문이다.
  `ord()` 로 바꿀 필요가 없다.

  ```python
  x = 'B'
  if 'A' <= x <= 'Z':          # ⭐ 파이썬은 이렇게 이어서 쓸 수 있다
      print("Upper case")
  ```

- ⭐ `'A' <= x and x <= 'Z'` 라고 길게 써도 되지만, **`'A' <= x <= 'Z'`** 가 짧고 읽기 쉽다.
  (수학에서 쓰는 모양 그대로다. 이게 되는 언어는 흔치 않다.)
- ⚠️⭐ **소문자가 대문자보다 "크다".** `'a'`(97) > `'Z'`(90) 이기 때문이다.

  ```python
  'a' > 'Z'       # True   ⚠️ 알파벳 순서가 아니라 번호 순서다
  'Z' < 'a'       # True
  ```

- ⚠️ 여러 글자를 비교하면 **사전순(앞 글자부터)** 이다.

  ```python
  'apple' < 'banana'     # True
  'abc' < 'abd'          # True
  '10' < '9'             # True   ⚠️ 숫자가 아니라 글자로 비교! '1' < '9'
  ```

### 글자 판별 함수 — `is...()` 집안

| 함수 | 묻는 것 | True 예 | False 예 |
| --- | --- | --- | --- |
| `.isalpha()` | 전부 **글자**인가 | `'ab'`, `'가'` | `'ab3'`, `''` |
| `.isdigit()` | 전부 **숫자**인가 | `'1'`, `'12'` | `'12a'`, `'-1'` |
| `.isalnum()` | 전부 **글자+숫자**인가 | `'ab3'`, `'A1'` | `'a b'`, `''` |
| `.isupper()` | **대문자**인가 | `'A'`, `'ABC'` | `'Abc'` |
| `.islower()` | **소문자**인가 | `'a'`, `'abc'` | `'Abc'` |
| `.isspace()` | 전부 **공백**인가 | `' '`, `'  '` | `'a '` |

```python
'a'.isalpha()      # True
'ab'.isalpha()     # True   ⭐ 한 글자가 아니어도 된다
'ab3'.isalpha()    # False  ← 하나라도 아니면 False
'12'.isdigit()     # True
'12a'.isdigit()    # False
```

- ⭐⭐ **"전부"가 핵심이다.** 하나라도 아니면 False. 한 글자씩 보려면 `for` 로 돈다.

### ⚠️ 빠지기 쉬운 함정 4가지

**① 빈 문자열은 전부 False**

```python
''.isalpha()     # False
''.isdigit()     # False
```

- ⚠️ `if s.isdigit():` 로 입력을 검사할 때, **빈 입력도 False** 라 자연히 걸러진다 (다행).

**② ⭐ 한글도 `isalpha()` 는 True**

```python
'가'.isalpha()      # True   ⚠️ "알파벳"이 아니라 "글자"를 뜻한다
'한글'.isalpha()    # True
```

- **"알파벳인가"가 아니라 "글자인가"** 다. 영어만 걸러내려면 **범위 비교**를 쓴다.

  ```python
  if 'a' <= c <= 'z' or 'A' <= c <= 'Z':     # ⭐ 영어만
  ```

**③ ⚠️⭐ 음수·소수는 `isdigit()` 이 False**

```python
'-1'.isdigit()     # False   ⚠️ 빼기 기호 때문
'1.5'.isdigit()    # False   ⚠️ 점 때문
```

- 음수까지 받아야 하면 **`int()` 를 `try` 로 감싸거나**, 맨 앞의 `-` 를 떼고 검사한다.

**④ 이상한 숫자들**

```python
'３'.isdigit()      # True    ← 전각 숫자
'②'.isdigit()      # True
'½'.isdigit()      # False   하지만 '½'.isnumeric() 은 True
```

- 엄밀히는 `isdecimal()` ⊂ `isdigit()` ⊂ `isnumeric()` 이다.
- ⭐ **코딩테스트에서는 `isdigit()` 로 충분**하다. 이런 입력은 안 나온다.

### ⭐⭐ 숫자도 "글자"다 — `'0' <= c <= '9'`

- ⭐⭐ **숫자를 골라낼 때 `int()` 로 바꿀 필요가 없다.** 숫자 글자도 아스키 번호가 **연속**이라
  알파벳과 **똑같이 범위 비교**가 된다.

  ```
  '0' = 48  '1' = 49  ...  '9' = 57      ← 연속!
  ```

  ```python
  c = '7'
  if '0' <= c <= '9':      # ⭐ int() 불필요
      print('숫자다')
  ```

- ⚠️ `int(c)` 로 바꿔서 `0 <= n <= 9` 를 검사하려 하면 **숫자가 아닐 때 ValueError**로 멈춘다.
  검사하려고 변환하는 건 **순서가 거꾸로**다.

  ```python
  int('@')        # ValueError: invalid literal for int()
  ```

- ⭐ **출력도 결국 문자열**이므로, 숫자 글자는 **바꾸지 말고 그대로 두는 게 맞다.**
  `'7'` → `7` → `'7'` 로 되돌릴 이유가 없다. (실제로 계산할 때만 `int()` 를 쓴다.)
- 정리하면 **구간은 세 개**뿐이고, 전부 같은 방식으로 쓴다.

  ```python
  '0' <= c <= '9'     # 숫자
  'A' <= c <= 'Z'     # 대문자
  'a' <= c <= 'z'     # 소문자
  ```

### ⚠️⭐ 오류 정리 — `'A' <= c <= 'z'` 는 왜 틀렸나

```python
if i >= 'A' and i <= 'z':     # ⚠️ 알파벳만 걸러낸다고 생각했지만…
    a += i
```

- ⭐⭐ **`'A'`(65) 와 `'z'`(122) 사이는 알파벳만 있는 게 아니다.** 가운데에 기호 6개가 숨어 있다.

```
대문자  65~ 90 : ABCDEFGHIJKLMNOPQRSTUVWXYZ
⚠️ 틈   91~ 96 : [ \ ] ^ _ `          ← 전부 통과해 버린다!
소문자  97~122 : abcdefghijklmnopqrstuvwxyz
```

| 입력 | 틀린 코드 | 정답 |
| --- | --- | --- |
| `'abcABC'` | `'ABCABC'` | `'ABCABC'` ✅ |
| `'a_b'` | `'A_B'` ❌ | `'AB'` |
| `'x[y]z'` | `'X[Y]Z'` ❌ | `'XYZ'` |
| `'hello world!'` | `'HELLOWORLD'` | `'HELLOWORLD'` ✅ |

- 공백·숫자·`!`·`-` 는 **구간 밖이라 잘 걸러진다.** 그래서 **어지간한 입력은 통과**하고,
  `_` 나 `[` 가 들어오는 순간에만 틀린다. (2번의 `aabb` 와 같은 **운 좋게 맞는** 유형)

**고치는 법 — 두 구간을 `or` 로 따로 본다**

```python
if 'A' <= c <= 'Z' or 'a' <= c <= 'z':
```

**더 간단히 — 먼저 한쪽으로 통일하면 구간이 하나가 된다 ⭐**

```python
s = input().upper()        # ⭐ 먼저 대문자로 (또는 .lower())
for c in s:
    if 'A' <= c <= 'Z':    # 구간 하나만 보면 된다
        a += c
```

- ⚠️ `list(input())` 의 `list()` 는 **필요 없다.** 문자열은 `for c in s:` 로 바로 한 글자씩 돈다.
  4번의 `list()` 는 **수정하려고** 쓴 것이다. **읽기만 할 땐 안 쓴다.** (1번의 `list(...split())` 과 같은 습관)

### ⭐⭐ 버릴 것을 나열하지 말고, 남길 것만 통과시킨다

> **문제**: 문자열에서 **영문자와 숫자만** 출력하되, 영문자는 모두 **소문자**로.

- 막히는 지점은 보통 두 가지인데, **둘 다 생각의 방향만 바꾸면** 풀린다.

| 막히는 생각 | 바꾼 생각 |
| --- | --- |
| 숫자를 고르려면 `int()` 로 바꿔야 하나? | 출력도 문자열 → **글자인 채로 둔다** |
| `@`, `#`, `$` … 전부 나열해야 하나? | 버릴 건 **무한**, 남길 건 **36개** → **통과 조건만** 쓴다 |

```python
s = input().lower()          # ⭐ 먼저 소문자로 통일 → 볼 구간이 하나로 줄어든다

a = ''
for c in s:
    if 'a' <= c <= 'z' or '0' <= c <= '9':    # ⭐ 남길 것만 통과
        a += c

print(a)
```

| 입력 | 출력 |
| --- | --- |
| `Hello, World! 123` | `helloworld123` |
| `a@b#c$1%2^3` | `abc123` |
| `ABC_xyz-789` | `abcxyz789` |
| `x[y]z_1` | `xyz1` |

- ⭐⭐ `@ # $ % ^` 도, `_` 도, 공백도 **아무것도 지정하지 않았는데** 전부 걸러진다.
  **통과 조건에 안 걸리면 자동으로 버려지기** 때문이다.
- ⭐ 이건 4번의 **"돌면서 지우지 말고 남길 것을 모아라"** 와 **같은 발상**이다.
  문자열 문제에서 계속 되풀이되는 사고방식이니 **틀로 기억해 둔다.**

**⚠️ `isalnum()` 한 줄로 줄이고 싶다면**

```python
print(''.join(c for c in input().lower() if c.isalnum()))              # ⚠️ 위험
print(''.join(c for c in input().lower() if c.isalnum() and c.isascii()))  # ⭐ 안전
```

- ⚠️ `isalnum()` 은 **한글도 True** 라서, `'안녕 Hi 42'` 가 **`'안녕hi42'`** 가 된다.
  `'１２３'` 같은 전각 숫자도 살아남는다.
- ⭐ **범위 비교가 더 안전하고 의도도 분명하다.** `isalnum()` 을 쓸 땐 `isascii()` 를 같이.

### 예시 코드

**① 대문자/소문자/숫자 세기**

```python
s = input()
upper = lower = digit = 0

for c in s:
    if c.isupper():
        upper += 1
    elif c.islower():
        lower += 1
    elif c.isdigit():
        digit += 1

print(upper, lower, digit)
```

**② `.upper()` 를 직접 만들기 — 아스키로**

```python
s = input()
result = []
for c in s:
    if 'a' <= c <= 'z':
        result.append(chr(ord(c) - 32))    # 소문자 → 대문자는 -32
    else:
        result.append(c)
print(''.join(result))
```

- ⭐ 실전에서는 **`.upper()` 를 쓴다.** 이 방식은 **"몇 칸 옮기기"** 문제를 위한 연습이다.

**③ ⭐ 알파벳 개수 세기 — 번호를 배열 index로**

```python
s = input()
cnt = [0] * 26

for c in s:
    cnt[ord(c) - ord('a')] += 1        # ⭐⭐ 'a'→0, 'b'→1, ... 'z'→25

for i in range(26):
    if cnt[i] > 0:
        print(chr(ord('a') + i), cnt[i])
```

- ⭐⭐ **`ord(c) - ord('a')` 로 글자를 배열 번호로 바꾸는 것**이 아스키의 가장 큰 쓸모다.
  ch7의 1차원 배열과 이어진다.

**④ 알파벳을 n칸 미는 암호 (카이사르)**

```python
s = input()
n = int(input())
result = []

for c in s:
    if c.isalpha():
        result.append(chr((ord(c) - ord('a') + n) % 26 + ord('a')))
    else:
        result.append(c)
print(''.join(result))
```

- ⭐⭐ **`% 26` 이 핵심**이다. `'z'` 에서 한 칸 더 가면 `'a'` 로 **돌아와야** 하기 때문.
  (ch3의 나머지 연산이 여기서 쓰인다.)

### ⚠️ 코드트리 자료의 오타

```python
x = 'B'
if 'A' <= x and x <= 'Z':
    print("Lower case")       # ⚠️ 대문자 조건인데 "Lower" 라고 찍는다
```

- 조건은 **대문자 검사**가 맞다. 출력 문구가 잘못됐을 뿐이니 **`"Upper case"`** 로 읽자.

### 주의할 점

- ⚠️⭐ **`ord()` 는 글자 하나만** 받는다. `ord('ab')` 는 **TypeError**.
- ⚠️ `chr()` / `ord()` 는 **점을 찍지 않는다.** `'A'.ord()` 가 아니라 **`ord('A')`** — 내장 함수다.
  (반대로 `isalpha()` 는 **점을 찍는다.** `s.isalpha()`)
- ⚠️⭐ `is...()` 는 **"전부"** 를 묻는다. 하나라도 아니면 False.
- ⚠️⭐ **빈 문자열은 전부 False.**
- ⚠️⭐ **한글도 `isalpha()` 가 True** — "알파벳"이 아니라 "글자"다. 영어만 보려면 범위 비교.
- ⚠️⭐ **소문자가 대문자보다 크다** (`'a'` 97 > `'Z'` 90). 알파벳 순서가 아니라 번호 순서다.
- ⚠️ `'-1'.isdigit()` 은 **False**. 음수 입력 검사에 그대로 쓰면 안 된다.
- ⚠️ 문자열끼리의 `<` 는 **사전순**이다. `'10' < '9'` 는 True — 숫자로 비교하려면 `int()`.
- ⚠️ 대소문자 차이 **32** 는 **알파벳에만** 해당한다. 숫자·기호에 `-32` 를 하면 엉뚱한 글자가 된다.
- ⭐ 범위 비교는 **`'A' <= x <= 'Z'`** 처럼 이어 쓸 수 있다 — `and` 로 길게 쓰지 않아도 된다.

## ✅ 한눈에 복습

- [ ] ⭐⭐ 나누는 일은 **`split()` 혼자** 한다 — `map`·`tuple`·`list`는 덤이다.
- [ ] ⭐ **`map(int, ...)` 은 "자르기"가 아니라 "타입 바꾸기"** — 문자열 문제엔 필요 없다.
- [ ] `split()`의 결과는 **언제나 문자열 리스트**. 숫자로 쓸 땐 `int()`를 거친다.
- [ ] ⭐ 개수를 알면 **`a, b = input().split()`** — 가장 짧은 형태.
- [ ] `tuple(...)`, `list(...)` 를 씌워도 **언패킹은 똑같이** 된다 (안 씌워도 됨).
- [ ] ⚠️ **`list(input().split())` 의 `list()`는 무의미** — `split()`이 이미 리스트다.
- [ ] 리스트 = 수정 가능 `[ ]`, 튜플 = 수정 불가 `( )` — 여기선 **기능 차이 없음**.
- [ ] ⚠️⭐ 개수가 안 맞으면 **ValueError** (`not enough` / `too many values to unpack`).
- [ ] ⚠️⭐ **줄이 다르면 `split()`이 아니다** — `input()`을 줄 수만큼 부른다.
- [ ] ⚠️ `'10' + '20'` 은 `'1020'` — 문자열 덧셈은 **이어붙이기**.
- [ ] ⚠️ `split()` 은 **빈 괄호**로. `split(' ')` 는 연속 공백에서 빈 문자열이 생긴다.

- [ ] 합칠 땐 **`' '.join(words)`** 또는 `print(*words)` — `split`의 반대.
- [ ] 개수를 모르면 **`words = input().split()`** 로 리스트째 받아 `for`로 돈다.
- [ ] ⭐⭐ 연속 덩어리 세기 = **같으면 `cnt += 1` / 다르면 확정하고 `cnt = 1`**.
- [ ] ⭐⭐ **마지막 묶음은 루프 밖에서 한 번 더 `append`** — 뒤에 다른 글자가 없으니까.
- [ ] ⚠️⭐ 마지막 글자를 **루프 안 `if`로 가로채면 안 된다** — 같은지 비교를 건너뛴다.
- [ ] ⚠️⭐ `cnt+1` 같은 식은 **"마지막이 앞과 같다"는 멋대로 한 가정**이다.
- [ ] ⚠️⭐ 테스트는 **끝 글자가 앞과 다른 입력**(`abcd`)으로 — `aabb`는 틀려도 통과한다.
- [ ] 새 묶음은 **`cnt = 1`** 부터. `ex = c` 와 **항상 같이** 바꾼다.
- [ ] "다음 글자와 비교"로 풀면 **`i + 1 < len(A)` 를 `and` 앞에** 둔다 (IndexError 방지).
- [ ] 길이는 **`len(''.join(arr))`** — 세는 `for`를 또 돌 필요 없다.
- [ ] `ex + cnt` 는 **TypeError** — `ex + str(cnt)` 또는 `f"{ex}{cnt}"`.
- [ ] ⚠️ 변수 이름에 **`sum`, `list`, `str`, `max`, `min`** 쓰지 않기 (내장 함수가 가려짐).
- [ ] 출력은 `print(i, end="")` 보다 **`print(''.join(arr))`** 가 안전.
- [ ] 같은 틀로 **최장 연속 길이**(`max` 갱신), **덩어리 개수**(`+= 1`)도 풀린다.
- [ ] ⭐⭐ 문자열 `in`은 **부분 문자열이 있나** — `'ab' in s` 한 줄.
- [ ] 슬라이싱 반복문과 **결과는 같지만**, `in`은 C로 짜여 있어 **훨씬 빠르다** (20만 글자에서 69배).
- [ ] 반복문이 느린 이유는 **`s[i:i+2]`가 매 바퀴 새 문자열을 만들기** 때문.
- [ ] ⚠️⭐ 직접 돌릴 땐 범위가 **`len(s) - len(t) + 1`** — `len(s) - 1`은 **2글자 전용**이다.
- [ ] ⚠️ 찾았으면 **`break`** — 없으면 끝까지 다 돈다.
- [ ] **있나 `in` / 어디 `find` / 몇 개 `count`** — 3형제로 외운다.
- [ ] ⚠️⭐ `find`는 없으면 **`-1`**(참!), `index`는 **ValueError**. `!= -1` 로 비교할 것.
- [ ] ⚠️ `'aaa'.count('aa')` 는 **`1`** — 겹치는 건 안 센다.
- [ ] 앞뒤 확인은 **`startswith()` / `endswith()`** — 슬라이싱보다 안전.
- [ ] 다음 위치를 찾으려면 **`s.find('ab', pos + 1)`** (`+1` 없으면 무한 루프).
- [ ] ⚠️⭐ **문자열 `in`은 "조각", 리스트 `in`은 "통째로"** — `'a' in ['ab']` 는 **False**.
- [ ] ⚠️ `in`은 **대소문자 구분** — 무시하려면 양쪽 다 `.lower()`.
- [ ] ⭐⭐ **"못 찾으면 -1"** 은 직접 만들 때도 쓰는 패턴 — `start_idx = -1` 로 시작해 두면 끝.
- [ ] ⭐ `find` 는 그 패턴이 **이미 들어 있는 함수** — 확인과 위치를 **한 번에** 한다.
- [ ] ⚠️⭐ `index` 는 **`in` 과 짝으로만** — 혼자 쓰면 ValueError로 멈춘다.
- [ ] ⚠️ `in` + `index` 는 **두 번 훑는다** — `find` 한 줄이 2배 빠르다.
- [ ] ⚠️⭐ 위치 문제에서 **`break` 를 빼면 가장 뒤 위치**가 남는다 (답이 틀린다).
- [ ] `s[i] == 'a' and s[i+1] == 'b'` 꼴은 **새 문자열을 안 만들어** 슬라이싱보다 낫다.
- [ ] ⚠️ `s[i+1]` 을 보면 범위는 **`range(len(s) - 1)`** — 안 그러면 IndexError.
- [ ] ⭐ 반복해 찾는 열쇠는 **두 번째 인자** — `s.find(t, pos)` / `s.index(t, pos)`.
- [ ] `index` 로 세려면 **`try/except ValueError`** 로 끝을 잡는다 (`find` 는 `-1` 로 끝).
- [ ] ⚠️ `pos` 전진을 빼먹으면 **무한 루프**.
- [ ] ⚠️⭐ `count()` 는 **겹침을 안 센다** — `'banana'.count('ana')` 는 `1`.
- [ ] ⭐⭐ **겹침까지 세려면 `pos += 1`** (`pos += len(t)` 가 아니라). 이때만 직접 짤 가치가 있다.
- [ ] ⚠️ `while t in s[pos:]` 는 **바퀴마다 새 문자열**을 만든다 — 쓰지 말 것.
- [ ] ⭐ `find` 인수는 **`(찾을 것, start, end)`** — 뒤 둘은 선택.
- [ ] `start` = "여기서부터", `end` = "여기까지"(**불포함**). 범위를 넘겨도 **에러가 아니라 `-1`**.
- [ ] ⭐⭐ 반환값은 **언제나 원본 기준** — `s[k:].find(...)` 는 **`+ k`** 를 직접 더해야 한다.
- [ ] ⭐ 그래서 **`s[k:].find(x)` 보다 `s.find(x, k)`** (보정 불필요 + 새 문자열 안 만듦).
- [ ] `rfind` 는 **찾는 방향만** 반대 — 위치는 여전히 **왼쪽에서** 센다.
- [ ] ⚠️ `find` 는 **문자열만** 받는다 — `find(97)` 은 TypeError.
- [ ] ⭐⭐ `index` / `rfind` / `rindex` / `count` 도 **인수 구조가 똑같다**.
- [ ] ⚠️⭐ `s[k] = c` 는 **TypeError** — 문자열은 **수정 불가**.
- [ ] ⭐⭐ 위치로 바꾸려면 **`list()` → 수정 → `''.join()`** 3단계.
- [ ] ⭐ 한 글자만이면 **슬라이싱** `s[:k] + c + s[k+1:]` 가 더 짧다 (⚠️ `s[k:]` 아님).
- [ ] `list(s)` 는 **한 글자씩** 쪼갠다 — `split()` 과 다르다 (`list('a b')` 는 공백도 원소).
- [ ] ⚠️ **점을 찍는 쪽이 구분자** — `''.join(arr)`, `arr.join('')` 아님.
- [ ] ⚠️⭐ `join` 은 **문자열 리스트만** — 숫자가 섞이면 `map(str, ...)` 로 변환.
- [ ] ⚠️ `''.join(arr)` 결과도 **다시 담아야** 한다.
- [ ] ⚠️⭐ `replace()` 는 **값으로** 바꾼다 — "n번째 글자"에는 못 쓴다.

- [ ] ⭐⭐ 반복문에서 문자열을 만들 땐 **`+=` 말고 리스트에 모았다가 `join`** (10만 글자에서 2.2배).
- [ ] 뒤집기는 **`s[::-1]`**, 정렬은 **`''.join(sorted(s))`** (sorted 는 리스트를 돌려준다).
- [ ] ⚠️ 인덱스가 **0부터인지 1부터인지** 매번 확인 — 1부터면 `k - 1`.
- [ ] ⭐⭐ **제거 = 바꾸기에서 새 글자를 뺀 것** — `s[:k] + s[k+1:]`.
- [ ] ⚠️⭐ 뒤쪽은 **`s[k+1:]`** — `s[k:]` 로 쓰면 **아무것도 안 지워진다**.

- [ ] ⚠️⭐ `arr = arr.pop(k)` 금지 — 리스트는 **원본이 직접 바뀐다**.
