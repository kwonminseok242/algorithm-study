## 1. 방향 정의 — 배열 순서와 문자 매핑이 어긋난다

### ① 내가 한 실수

```python
dxs, dys = [0, 1, 0, -1], [1, 0, -1, 0]     # 0:오른쪽 1:아래 2:왼쪽 3:위
...
if d == 'L':
    dir_num = 3          # ⚠️ 3 은 "위"다. 왼쪽은 2
elif d == 'U':
    dir_num = 3          # 'L' 과 'U' 가 같은 동작을 한다
```

### ② 왜 틀렸나

**`dir_num` 은 "현재 방향 인덱스"일 뿐이고, 몇 번이 어느 방향인지는 내가 만든 배열 순서가 정한다.**
정해진 관례가 없다. 그래서 **배열과 매핑을 따로 적으면 반드시 어긋난다.**

### ③ 올바른 코드

```python
#       오른쪽  아래  왼쪽   위
dxs = [    0,    1,    0,   -1]
dys = [    1,    0,   -1,    0]
mapper = {'R': 0, 'D': 1, 'L': 2, 'U': 3}     # ⭐ 주석 순서 그대로

dir_num = mapper[d]
```

- `if`/`elif` 네 개가 한 줄로 줄고, **블록을 복붙하다 한 군데만 고치는 사고**가 사라진다.
- 없는 키는 `KeyError`. 입력에 공백·줄바꿈이 섞이면 `.strip()` 으로 다듬는다.

### ④ 체크포인트

> **배열 위에 방향 이름을 주석으로 적고, `mapper` 를 그 순서 그대로 쓴다.**

## 2. 격자(행·열) vs 좌표평면(x·y)

### ① 내가 한 실수

```python
# 좌표평면 문제인데 격자 감각으로
dirs = {'N': (1, 0), 'S': (-1, 0)}      # ⚠️ N 인데 x 를 건드린다
```

### ② 왜 틀렸나

**두 좌표계는 축도 다르고 방향도 반대다.**

| | 격자 (행·열) | 좌표평면 (x·y) |
| --- | --- | --- |
| `x` | **행** (세로 번호) | **가로** |
| `y` | **열** (가로 번호) | **세로** |
| 아래로 | `x + 1` | `y - 1` |
| 위(N)로 | `x - 1` | **`y + 1`** |

- ⚠️ 격자에서는 **아래가 `+`**, 좌표평면에서는 **위가 `+`** 다.
- `N`/`S` 를 뒤바꿔도 **대칭인 문제(원점 복귀 등)는 우연히 통과한다.** 위치를 출력하는 문제에서 터진다.

### ③ 올바른 코드

```python
# 격자 문제 (행, 열)
dxs, dys = [0, 1, 0, -1], [1, 0, -1, 0]     # 우 하 좌 상

# 좌표평면 문제 (x, y)
dirs = {'N': (0, 1), 'S': (0, -1), 'E': (1, 0), 'W': (-1, 0)}   # ⭐ N 은 y+1
```

### ④ 체크포인트

> **문제가 "행·열"로 말하는지 "좌표"로 말하는지 먼저 읽고, 방향표를 그 자리에서 다시 적는다.**

## 3. 범위 검사 — 무엇을, 어디까지

### ① 내가 한 실수

```python
if in_range(x, y):                       # ⚠️ ㉠ 지금 서 있는 칸을 검사
    x, y = x + dxs[d], y + dys[d]

def in_range(x, y):
    return 0 <= x < n - 1 and 0 <= y < n - 1   # ⚠️ ㉡ 마지막 행·열을 벽 취급
```

### ② 왜 틀렸나

- **㉠ 지금 칸은 언제나 격자 안이다.** `else` 가 한 번도 실행되지 않아 **벽을 그냥 통과한다.**
  한 칸 나간 **뒤에야** 알아채고, `else` 에는 이동이 없어서 **격자 밖에 얼어붙는다.**
- **㉡ 유효한 인덱스는 `0 ~ n-1`.** `x < n - 1` 로 쓰면 `n=3` 일 때 **마지막 행 `x=2` 가 `False`** 가 된다.

### ③ 올바른 코드

```python
def in_range(x, y):
    return 0 <= x < n and 0 <= y < n       # ⭐ n-1 이 아니라 n

nx, ny = x + dxs[d], y + dys[d]            # ⭐ ① 재 보고
if in_range(nx, ny):                       # ⭐ ② 갈 자리를 묻고
    x, y = nx, ny                          # ⭐ ③ 그제야 옮긴다
else:
    d = (d + 2) % 4
```

- **`< n` 이 맞는 이유:** `0 <= x < n` 은 "칸이 `n` 개"를 그대로 옮긴 식이다. `-1` 은 어디에도 안 들어간다.
- ⚠️ 출력에 `-1` 이나 `n` 같은 **격자 밖 좌표가 보이면** 범위 검사가 일을 안 하고 있다는 신호.

### ④ 체크포인트

> **검사 대상은 언제나 `nx, ny`. 경계는 `< n`(`n-1` 아님).**

## 4. n(행)과 m(열) 혼동 — 세 곳에 똑같이

### ① 내가 한 실수

```python
n, m = 3, 5                                  # 3행 5열
a = [[0] * n for _ in range(m)]              # ⚠️ 5행 3열이 만들어진다
...
return 0 <= x < n and 0 <= y < n             # ⚠️ y 도 n 으로 검사
```

### ② 왜 틀렸나

**`n`·`m` 이 쓰이는 자리가 세 곳인데, 한 곳만 틀려도 전부 어긋난다.**

```
a = [[0]*m for _ in range(n)]     ① 배열 생성   안쪽이 열(m), 바깥이 행(n)
0 <= x < n and 0 <= y < m         ② 범위 검사
for i in range(n): for j in range(m)   ③ 출력
```

- ①을 뒤집으면 `IndexError`, ②에서 `y < n` 으로 쓰면 **3~4열을 벽 취급**해서 조용히 틀린다.

### ③ 올바른 코드

```python
a = [[0] * m for _ in range(n)]              # ⭐ n행 m열

def in_range(x, y):
    return 0 <= x < n and 0 <= y < m         # ⭐ x↔n, y↔m

for i in range(n):
    print(*a[i])                             # ⭐ 행 n 번, 열은 알아서
```

### ④ 체크포인트

> **`x = 행 = n`, `y = 열 = m` 을 적어 놓고 ①생성 ②검사 ③출력 세 곳에 똑같이 적용한다.**

## 5. 방향 전환 — 고정값을 넣으면 한 번만 먹는다

### ① 내가 한 실수

```python
else:
    dir_num = 1          # ⚠️ 위에서 튕겼으니 아래로… 그 다음은?
```

### ② 왜 틀렸나

**아래 벽에 닿아도 다시 `1`(아래)이 되어 두 번째 튕김에서 멈춘다.**
방향 전환은 **"지금 방향을 기준으로" 바꿔야** 몇 번이든 된다.

### ③ 올바른 코드

**방향 배열을 시계방향 순서(`우 → 하 → 좌 → 상`)로 두면 전부 산술로 풀린다.**

```python
dxs, dys = [0, 1, 0, -1], [1, 0, -1, 0]

d = (d + 1) % 4      # ⭐ 시계방향 90도
d = (d + 2) % 4      # ⭐ 반대 방향
d = (d + 3) % 4      # ⭐ 반시계방향 90도  (= (d - 1) % 4)
```

- ⚠️ **`% 4` 를 빼먹으면** 네 번째 회전에서 `IndexError`.
- ⚠️ **이 공식은 "시계방향으로 배열했기 때문에" 되는 것이다.** 순서를 바꾸면 공식도 바뀐다.

### ④ 체크포인트

> **방향 배열은 시계방향으로 두고, 전환은 항상 `(d + k) % 4`. 고정값 대입 금지.**

## 6. 시뮬레이션 단위 — 한 번에 점프하면 중간을 놓친다

### ① 내가 한 실수

```python
for _ in range(n):
    d, dist = input().split()
    dx, dy = dirs[d]
    x, y = x + dx * int(dist), y + dy * int(dist)   # ⚠️ 거리만큼 한 번에
    t += int(dist)

if x == 0 and y == 0:        # ⚠️ 모든 이동이 끝난 뒤 한 번만 확인
    print(t)
```

### ② 왜 틀렸나

**"처음으로" 원점에 돌아온 시각을 묻는데, 중간에 지나간 걸 못 본다.**
`1초에 한 칸`이라고 했으면 **1초 = 1칸 = 확인 1번**이다.

```
E 1, W 2, E 1   →  (1,0) (0,0) (-1,0) (0,0)
                          ↑ 2초에 이미 지났다
   점프 방식: 4초   정답: 2초
```

### ③ 올바른 코드

```python
for _ in range(n):
    d, dist = input().split()
    dx, dy = dirs[d]
    for _ in range(int(dist)):      # ⭐ 1칸씩
        x, y = x + dx, y + dy
        t += 1
        if x == 0 and y == 0:       # ⭐ 매 칸 확인
            answer = t
            break
    if answer != -1:
        break
```

### ④ 체크포인트

> **"처음으로 / 몇 초 뒤에"가 보이면 1칸씩 돌리고 매 칸 확인한다.**

## 7. 이중 루프 탈출 — `break` 는 하나만 빠져나간다

### ① 내가 한 실수

```python
for d, dist in moves:
    for _ in range(dist):
        ...
        if x == 0 and y == 0:
            answer = t
            break               # ⚠️ 안쪽만 끝난다
# 바깥 루프는 계속 돌아 answer 가 덮어써진다
```

### ② 왜 틀렸나

**`break` 는 가장 가까운 반복문 하나만 빠져나간다.** 바깥 루프는 끝까지 돈다.
그래서 **나중에 다시 원점에 오면 `answer` 가 덮어써져** "처음" 돌아온 시각이 아니게 된다.

```
N1 S1 N1 S1  →  2초에 처음 복귀   하지만 4초로 덮어써진다
```

### ③ 올바른 코드

**방법 ① 플래그로 바깥에서 한 번 더 — 코테에서 가장 흔한 꼴**

```python
answer = -1                     # ⭐ "못 찾음"을 -1 로 표현
for d, dist in moves:
    for _ in range(dist):
        ...
        if x == 0 and y == 0:
            answer = t
            break
    if answer != -1:            # ⭐ 바깥도 끊는다
        break
print(answer)
```

**방법 ② 함수로 감싸고 `return` — 더 깔끔하다**

```python
def solve():
    for d, dist in moves:
        for _ in range(dist):
            ...
            if x == 0 and y == 0:
                return t         # ⭐ 몇 겹이든 한 번에 빠져나온다
    return -1

print(solve())
```

### ④ 체크포인트

> **안쪽에 `break` 를 썼으면 바깥에도 탈출을 적었는지 바로 확인한다. 아니면 함수 + `return`.**

## 8. 자잘하지만 자주 틀린 것

### ⓐ 0-based 로 계산하고 그대로 출력

```python
x, y = int(r) - 1, int(c) - 1      # 입력 직후 -1
...
print(x, y)                        # ⚠️ 되돌리지 않았다
print(x + 1, y + 1)                # ⭐
```

> **변환은 입력 직후와 출력 직전, 딱 두 군데서만.**

### ⓑ `dir` 를 변수명으로 쓰기

```python
dir = 'N'          # ⚠️ 파이썬 내장 함수 dir() 을 덮어쓴다
dir([])            # TypeError: 'str' object is not callable
```

> **`dir`, `max`, `min`, `sum`, `list`, `input` 은 변수명으로 쓰지 않는다. `dirs`, `d` 로.**

### ⓒ 한 줄 출력

```python
for v in row:
    print(v, end=' ')
print()

print(*row)        # ⭐ 같은 결과, 한 줄
```

> **리스트를 공백 구분으로 찍을 땐 `print(*row)`.**

### ⓓ 방향별로 같은 `while` 을 네 번 복붙

> **같은 코드를 네 번 쓰고 있으면 멈춘다. 배열이나 `dict` 로 줄어든다.**
> 복붙은 버그를 네 배로 늘리고, 그중 하나만 고치게 만든다. (1번 항목의 원인이 이것이었다)

## ✅ 격자 문제 풀기 전 체크리스트

- [ ] **좌표계부터 정한다** — 격자(행·열)인가 좌표평면(x·y)인가. 격자는 아래가 `x+1`, 좌표평면은 위가 `y+1`.
- [ ] **방향 배열을 시계방향으로 적고 바로 위에 이름을 주석으로 단다.** `mapper` 는 그 순서 그대로.
- [ ] **`x = 행 = n`, `y = 열 = m`** 을 ①배열 생성 ②`in_range` ③출력 **세 곳에 똑같이** 적용한다.
- [ ] **`in_range` 는 `nx, ny` 에 대해, 경계는 `< n`** (`n-1` 아님). 조건은 **범위 검사를 맨 앞에**.
- [ ] **방향 전환은 `(d + k) % 4`** — `+1` 시계, `+2` 반대, `+3` 반시계. 고정값 대입 금지.
- [ ] **"처음으로 / 몇 초 뒤"가 나오면 1칸씩 돌리고 매 칸 확인**한다. 점프하면 중간을 놓친다.
- [ ] **안쪽에 `break` 를 썼으면 바깥 탈출도 적는다.** 또는 함수로 감싸 `return`. `answer = -1` 로 "못 찾음" 표현.
- [ ] **제출 직전:** 0-based 를 되돌렸나(`+1`), `dir` 같은 내장 이름을 안 썼나, 같은 블록을 복붙하지 않았나.
