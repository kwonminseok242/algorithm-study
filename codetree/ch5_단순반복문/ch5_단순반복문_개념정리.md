## 1. 세미콜론(`;`) — 파이썬에서도 쓸 수 있다

### 핵심 요약

- `;`는 C나 Java 전용이 아니다. **파이썬에서도 문법적으로 유효**하다.
- 다만 **역할이 다르다.**
  - **C / Java** → 문장이 끝났음을 알리는 **필수 종결 기호**. 빼면 에러.
  - **파이썬** → 한 줄에 문장을 여러 개 넣을 때 쓰는 **선택 구분자**. 없어도 된다.
- 파이썬은 원래 **줄바꿈**으로 문장을 구분한다. 그래서 `;`는 "줄바꿈 대신 쓰는 것"일 뿐이다.
- 붙여도 에러는 안 나지만, **파이썬답지 않은 코드**다. (PEP 8 비권장)



### 예시 코드

**한 줄에 여러 문장 —** `;`**의 유일한 쓸모**

```python
q = 0; s = 1; t = 1
```

```python
# 위 한 줄은 아래 세 줄과 완전히 같다
q = 0
s = 1
t = 1
```

**줄 끝에 붙이는** `;`**는 그냥 군더더기**

```python
a = 1;        # 에러는 안 남. 하지만 아무 의미 없음
print(a);     # C/Java 습관이 남은 코드
```

**파이썬다운 방법 — 다중 대입** ⭐

```python
q, s, t = 0, 1, 1     # ; 없이 한 줄에 세 변수 초기화
```

**실제로 본 코드 (피보나치)**

```python
q = 0; s = 1; t = 1
for i in range(4):
    q = s + t
    t = s
    s = q
print(q)
```

```
8
```

값이 어떻게 굴러가는지 손으로 따라가 보기 — `t`(이전 값)와 `s`(현재 값)를 더해 `q`에 넣고, 한 칸씩 밀어 준다.


| i   | `q = s + t` | `t = s` | `s = q` |
| --- | ----------- | ------- | ------- |
| 시작  | 0           | 1       | 1       |
| 0   | 2           | 1       | 2       |
| 1   | 3           | 2       | 3       |
| 2   | 5           | 3       | 5       |
| 3   | **8**       | 5       | 8       |




### 주의할 점

- ⚠️ `;`를 봤다고 **"이건 파이썬이 아니네"라고 판단하면 안 된다.** 시험 문제에서 헷갈리기 쉬운 부분.
- `;`로는 **한 줄짜리 문장만** 이어 붙일 수 있다. `for`, `if`처럼 **콜론(**`:`**)으로 블록을 여는 문장**은 이렇게 못 붙인다.
  ```python
  for i in range(3); print(i)    # ❌ SyntaxError
  ```
- 초기화 값이 여러 개일 땐 `;`보다 **다중 대입(**`q, s, t = 0, 1, 1`**)** 이 표준이다.
- 반대로 **줄바꿈은 파이썬에서 문법**이다. C/Java처럼 "`;`만 있으면 줄은 마음대로"가 아니다. (ch4의 들여쓰기와 같은 맥락)
- 값을 밀어 주는 코드는 **대입 순서가 생명**이다. 위 코드에서 `t = s`와 `s = q`의 순서를 바꾸면 결과가 달라진다. 헷갈리면 **표를 그려서 한 줄씩 손으로 굴려 보자.**

## 2. `range(a, b, -1)` — 거꾸로 세기, 첫 번째 자리가 무조건 시작값



### 핵심 요약

- `range`는 **값의 크기를 전혀 보지 않는다.** 적어 준 **위치 그대로** 해석한다.
  ```
  range(start, stop, step)
  ```
- **첫 번째 자리 = 시작값**, **두 번째 자리 = 끝값(항상 제외)**, **세 번째 자리 = 한 번에 더할 양**.
- ⚠️ 그래서 **"작은 값이 먼저 온다"는 규칙은 없다.** `range(10, 4, -1)`은 10에서 시작한다.
- `-1`은 **"순서를 뒤집어라"가 아니라 "매번 -1을 더해라"** 라는 뜻이다.
- 끝값(`stop`)은 **어느 방향이든 제외**된다.
  - 증가(`+1`) → `b - 1`까지
  - 감소(`-1`) → `b + 1`까지



### 예시 코드

**10부터 5까지 1씩 감소** ⭐

```python
for i in range(10, 4, -1):
    print(i)

print("Done")
```

```
10
9
8
7
6
5
Done
```

- 시작 `10` → `-1`씩 → `5` → 다음은 `4`인데 `4`**는 stop이라 제외** → 멈춤.
- 그래서 **5까지 출력하려면 stop에 4**를 적는다. (`b + 1`까지 나온다)

**"작은 값이 먼저"가 아니라는 증거 — 순서를 바꾸면 빈 range**

```python
for i in range(4, 10, -1):
    print(i)
print("Done")
```

```
Done
```

- `4`에서 시작해 `-1`씩 가면 `10`에서 **점점 멀어진다** → 시작하자마자 끝 → 아무것도 출력 안 됨.
- 파이썬이 알아서 작은 값을 앞에 놓아 준다면 여기서도 `4,5,6...`이 나와야 하는데, 나오지 않는다.

**방향과 step이 어긋나도 에러가 아니다 (조용히 0번 반복)**

```python
range(10, 4)        # step 생략 = +1 → 빈 range
range(4, 10, -1)    # 빈 range
list(range(10, 4))  # []
```

**증가 vs 감소 비교**

```python
range(1, 5)          # 1 2 3 4      (5 제외)
range(1, 5, 2)       # 1 3          (2씩 증가)
range(5, 0, -1)      # 5 4 3 2 1    (0 제외)
range(4, 10, -1)     # (빈 range)
```



### 주의할 점

- ⚠️ **"10을 먼저 써도 작은 값부터 시작하나?" → 아니다.** 첫 번째 자리가 곧 시작값이다.
- ⚠️ 감소 반복문에서 `step`을 빼먹으면(`range(10, 4)`) **에러 없이 0번 반복**한다. 가장 찾기 힘든 버그.
- 끝값을 정할 때 **1칸 실수**가 잦다. "**5까지 나오게 하려면 4를 적는다**" — 마지막 값보다 **1 작게**.
- `-2`, `-3`도 된다. `range(10, 0, -3)` → `10 7 4 1`
- **외우는 법:** `-1`이 보이면 화살표가 왼쪽(←)이라고 생각하고, **큰 값 → 작은 값** 순으로 직접 써 준다.
- 헷갈리면 `print(list(range(...)))`로 **실제 숫자를 눈으로 확인**하고 넘어가자.

## 3. 오류 정리 — start는 포함, stop만 제외 (양쪽 다 밀지 말기)



### 핵심 요약

- "끝값은 출력되지 않는다"를 **양쪽 끝에 다 적용하는 실수**가 잦다.
- **start는 제외되지 않는다. 그대로 출력된다.** 조정할 자리는 **stop 하나뿐**이다.
- 두 자리는 성격 자체가 다르다.
  - **start** = "여기**서부터**" → **포함** (원하는 첫 값을 그대로 쓴다)
  - **stop** = "여기 오면 **멈춰**" → **제외** (한 칸 더 간 값을 쓴다)
- 감소 반복의 공식 ⭐
  ```
  range(첫 출력값, 마지막 출력값 - 1, -1)
  ```



### 예시 코드

**"17부터 5까지 1씩 감소" — 세 가지를 나란히 비교**

```python
list(range(5, 18, -1))   # []                       ← 방향이 반대 (2번 개념)
list(range(17, 4, -1))   # [17, 16, ... , 6, 5]     ← 정답 ✅
list(range(18, 5, -1))   # [18, 17, ... , 7, 6]     ← 양쪽이 한 칸씩 밀림 ❌
```


|                    | 첫 값  | 마지막 값 |
| ------------------ | ---- | ----- |
| 원하는 것              | 17   | 5     |
| `range(17, 4, -1)` | 17 ✅ | 5 ✅   |
| `range(18, 5, -1)` | 18 ❌ | 6 ❌   |


**정답 코드**

```python
for i in range(17, 4, -1):
    print(i, end=' ')
```

```
17 16 15 14 13 12 11 10 9 8 7 6 5
```

**증가일 때도 규칙은 똑같다 (start 포함 / stop 제외)**

```python
list(range(5, 18))       # [5, 6, ... , 17]   → 5부터 17까지
# 5는 그대로 나오고, 18만 빠진다
```



### 주의할 점

- ⚠️ **start에는 절대 ±1을 하지 않는다.** 원하는 첫 값을 그대로 적는다.
- 감소는 `마지막 값 - 1`, 증가는 `마지막 값 + 1`을 stop에 적는다. (**stop은 늘 한 칸 바깥**)
- 이 실수는 **에러가 안 난다.** 개수는 13개로 똑같고 값만 1씩 밀려서 나오므로 **눈으로 놓치기 쉽다.**
- 확인 습관: **첫 값과 마지막 값 둘만** 보자. 둘 다 맞으면 사이는 자동으로 맞다.
- 손으로 확인할 땐 `print(list(range(...)))`가 가장 빠르다. (2번 개념과 동일)

## 4. 반복문에서 한 줄로 붙여 출력하기 — `end=""`



### 핵심 요약

- `print`는 출력이 끝나면 **자동으로** `\n`**(줄바꿈)을 붙인다.** 이게 `end`의 **기본값**이다.
  ```python
  print("A")            # print("A", end="\n") 과 같다
  ```
- 그래서 반복문에서 그냥 출력하면 **한 줄에 하나씩** 세로로 찍힌다.
- `end=""` (빈 문자열)로 덮어쓰면 줄바꿈이 사라져 **옆으로 붙어서** 출력된다.
- `end`에 넣은 문자열이 **매번 값 뒤에 붙는다.** 공백을 넣으면 띄어쓰기가 된다.



### 예시 코드

**기본 — 세로로 출력된다**

```python
n = int(input())
for i in range(n):
    print("A")
```

```
>> 3
A
A
A
```

`end=""` **— 전부 붙여서 출력** ⭐

```python
n = int(input())
for i in range(n):
    print("A", end="")
```

```
>> 3
AAA
```

`end=" "` **— 한 칸씩 띄어서 (코딩테스트에서 가장 많이 쓴다)**

```python
for i in range(1, 4):
    print(i, end=' ')
```

```
1 2 3 
```

**반복이 끝난 뒤에는 줄바꿈을 직접 해 준다**

```python
for i in range(3):
    print("A", end="")
print()              # ← 빈 print() 하나로 줄바꿈
print("다음 줄")
```

```
AAA
다음 줄
```

**같은 문자 반복이면 반복문 없이도 된다**

```python
n = int(input())
print("A" * n)       # AAA
```



### 주의할 점

- ⚠️ `end=""`(빈 문자열)와 `end=" "`(공백 한 칸)는 **다르다.** 따옴표 사이를 잘 보자.
- ⚠️ `end=""`로 끝내면 **줄바꿈이 없는 상태로 남는다.** 뒤에 다른 출력이 있으면 그대로 이어 붙는다. → 반복 후 `print()` **한 줄** 습관.
- `end`는 **키워드 인자**라 `print("A", "")` 처럼 값만 넘기면 안 된다. 반드시 `end=`를 적는다.
- `sep`과 헷갈리지 말 것. `sep`**은 값들 사이**, `end`**는 맨 끝**. (ch1 복습)
- `end=' '`로 출력하면 **마지막에도 공백이 하나 남는다.** 보통 채점에 영향은 없지만 알아 두자.

## 5. 언더스코어 `_` — 쓰지 않는 반복 변수



### 핵심 요약

- 반복 변수(`i`)를 **블록 안에서 한 번도 쓰지 않을 때**, 이름 대신 **`_`**를 쓴다.
- 뜻은 **"이 값은 쓰지 않겠다"** 는 신호다. **횟수만 필요할 때** 쓴다.
- ⚠️ **문법이 아니라 관례**다. `_`도 그냥 **평범한 변수 이름**일 뿐이고, 값은 실제로 들어간다.
- 가독성을 위한 것이다. 읽는 사람이 "`i`가 어디 쓰이지?" 하고 찾지 않아도 된다.



### 예시 코드

`i`**를 안 쓰는 경우 →** `_`**로** ⭐

```python
n = int(input())
for _ in range(n):
    print("A", end="")
```

```
>> 3
AAA
```

**판단 기준 — 블록 안에서 그 변수를 읽는가?**

```python
for i in range(n):
    print(i)        # i를 읽는다  → i 그대로 쓴다
```

```python
for _ in range(n):
    print("A")      # 횟수만 필요 → _ 를 쓴다
```

`_`**에도 값은 들어간다 (특별한 문법이 아니라는 증거)**

```python
for _ in range(3):
    print(_, end=' ')
```

```
0 1 2
```



### 주의할 점

- `_`는 **안 쓸 때만** 쓴다. 안에서 값을 써야 하면 `i`처럼 **의미 있는 이름**을 붙인다.
- 문법이 아니므로 `_` **대신** `i`**를 써도 에러가 아니다.** 스타일 문제다.
- 대화형 셸(`>>>`)에서는 `_`가 **마지막 결과값**을 담는 특별한 의미가 있다. 스크립트에서는 무관.
- 코딩테스트 입력에서도 자주 쓴다 — **줄 수만 알고 값은 나중에 읽을 때**:
  ```python
  for _ in range(n):
      a, b = map(int, input().split())
  ```

## 6. 정답 정리 — A/B 출력, float로는 풀 수 없는 문제 (긴 나눗셈)

> **문제:** 두 정수 `A`, `B`를 입력받아 `A/B`를 **소수점 21번째 자리에서 내림하여**(= 소수 20자리까지) 출력하기.
> `14 3` → `4.66666666666666666666`



### 핵심 요약

- **내가 쓴 코드**
  ```python
  A, B = map(int, input().split())
  print(f"{A/B:.20f}")       # → 4.66666666666666696273  ❌
  ```
- 틀린 이유가 **두 가지**다.
  1. ⭐ **float의 정밀도 한계** — 파이썬 float는 **유효숫자 약 17자리**가 끝이다. `A/B`를 계산하는 **순간 이미 값이 변질**된다.
  2. `:.20f`는 **반올림**이다. 문제가 요구한 **내림**이 아니다.
- **서식(**`.20f`**)을 늘려도 없는 정확도는 생기지 않는다.** 변질된 값을 20자리까지 성실히 찍어 줄 뿐이다.
- 해결책: **실수를 아예 쓰지 않고, 정수 연산(**`//`**,** `%`**)만으로 한 자리씩 만든다.** → 긴 나눗셈



### 예시 코드

**float에 담긴 진짜 값 확인하기**

```python
from decimal import Decimal
print(Decimal(14/3))
```

```
4.66666666666666696272613990004174411296844482421875
```

```
내 출력 : 4.66666666666666696273
정답    : 4.66666666666666666666
                         ↑ 17번째 소수 자리부터 틀어진다
```

**정답 — 긴 나눗셈을 반복문으로** ⭐

```python
A, B = map(int, input().split())

print(A // B, end='.')       # 정수부 + 소수점
r = A % B                    # 나머지
for _ in range(20):
    r *= 10
    print(r // B, end='')    # 소수 한 자리
    r %= B
print()
```

```
>> 14 3
4.66666666666666666666
```

**원리 — 초등학교 세로셈 그대로 (수학 지식 필요 없음)**

```
      4. 6  6  6
    ┌──────────
 3  │ 14
      12
    ─────
       2 0        ← 나머지 2 에 0을 "내려씀"   = r *= 10
       1 8
    ─────
         2 0      ← 또 0을 내려씀
         1 8
    ─────
           2
```

| 세로셈에서 하는 일 | 코드 |
|---|---|
| 나머지 옆에 **0을 내려쓴다** | `r *= 10` |
| 나누어서 **몫을 위에 적는다** | `print(r // B, end='')` |
| **새 나머지**를 아래 남긴다 | `r %= B` |

**왜 `r` 하나만 굴리면 되는가**

```
14/3  =  4  +  2/3
         ↑      ↑
       A//B   (A%B)/B   ← 정수부는 끝났고, 남은 건 이 분수뿐
```

- 정수부 `A // B`는 이미 출력했다. 이제 **남은 `r/B`의 소수 자리만** 뽑아내면 된다.
- `r`은 항상 **"아직 안 쓴 나머지"**. `r < B`이므로 `r / B`는 늘 **0과 1 사이**다.
- 거기에 10을 곱하면 **소수점이 한 칸 밀려서, 다음 자리가 정수부 위치로 올라온다.**
  ```
  2/3 = 0.666...   →  ×10  →  20/3 = 6.666...
                                     ↑
                          정수부 6 이 곧 소수 첫째 자리
  ```
- 그래서 `//`로 떼어내면 그게 **다음 숫자**, `%`로 남기면 그게 **다음 회차의 `r`** 이다.

**값 따라가기 (14 ÷ 3)**


| 회차  | `r *= 10`        | `r // B` (출력) | `r %= B` |
| --- | ---------------- | ------------- | -------- |
| 시작  | `r = 14 % 3 = 2` | —             | —        |
| 1   | 20               | **6**         | 2        |
| 2   | 20               | **6**         | 2        |
| 3   | 20               | **6**         | 2        |
| …   | …                | …             | …        |


- **버리는 것이 곧 내림**이다. 따로 처리할 게 없다.
- 자릿수 제한이 없다. `range(20)`을 `range(100)`으로 바꾸면 100자리도 정확하다.

**다른 방법 —** `Decimal`

```python
from decimal import Decimal, getcontext, ROUND_DOWN
getcontext().prec = 50

A, B = map(int, input().split())
print((Decimal(A) / Decimal(B)).quantize(Decimal('1.' + '0' * 20), rounding=ROUND_DOWN))
```



### 주의할 점

- ⚠️ `Decimal(A/B)`**는 이미 늦었다.** 괄호 안에서 float 나눗셈이 먼저 끝나 값이 변질된 뒤다.
반드시 `Decimal(A) / Decimal(B)` 로 **정수부터** 감싼다.
- ⚠️ 소수 **17자리 이상**을 요구하는 문제가 보이면 `/`**와** `:.Nf`**는 쓰면 안 된다**는 신호다.
- `:.20f`는 **반올림**, 문제의 "내림"과 다르다. 정수 연산은 버리므로 자동으로 내림이 된다.
- 예제 1개만 맞춰 보고 넘어가면 놓친다. **앞 16자리는 멀쩡하게 맞기 때문**이다.
- `print(A // B, end='.')` — 정수부와 소수점을 한 번에. `//`(몫)와 `/`(항상 float)를 구분하자. (ch3 복습)
- 긴 나눗셈은 `r`이 `0`이 되면 그 뒤는 계속 `0`이 나온다 (딱 나누어떨어지는 경우). 그대로 두면 된다.

  **1 ÷ 4 = 0.25 따라가기**

  | 회차 | `r *= 10` | `r // B` (출력) | `r %= B` |
  |---|---|---|---|
  | 시작 | `r = 1 % 4 = 1` | — | — |
  | 1 | 10 | **2** | 2 |
  | 2 | 20 | **5** | 0 |
  | 3 | 0 | **0** | 0 |
  | 4 | 0 | **0** | 0 |

  → `0.25000...` 나머지가 0이 되면 뒤는 **자동으로 0이 채워진다.**

## 7. 오류 정리 — 초기화는 반복문 밖, 갱신은 반복문 안

### 핵심 요약
- **내가 쓴 코드**
  ```python
  print(A // B, end='.')
  for _ in range(20):
      r = A % B       # ← 초기화가 반복문 "안"에 있다
      r *= 10
      k = r // B
      print(k, end='')
  ```
- `A`와 `B`는 **절대 변하지 않는다.** 그런데 `r = A % B`가 반복문 안에 있으니 매 회차마다 `r`이 **똑같은 값으로 되돌아간다.**
- 결과: 20번 모두 **완전히 같은 계산** → **같은 숫자만 20번** 출력된다.
- 빠진 것은 **`r %= B`** 한 줄. 세로셈에서 **새 나머지를 아래에 남기는** 동작이다. 이게 없으면 다음 자리로 못 넘어간다.
- 원칙 ⭐ **초기화는 반복문 밖, 갱신은 반복문 안.**

### 예시 코드

**⚠️ `14 3`으로만 테스트하면 정답처럼 보인다**
```
 14/3   내 코드: 4.66666666666666666666   정답: 4.66666666666666666666   ✅ 우연히 통과
  1/4   내 코드: 0.22222222222222222222   정답: 0.25000000000000000000   ❌
  1/7   내 코드: 0.11111111111111111111   정답: 0.14285714285714285714   ❌
 22/7   내 코드: 3.11111111111111111111   정답: 3.14285714285714285714   ❌
```
- `0.666...`은 **마침 전부 같은 숫자**라서 버그가 드러나지 않았다.

**값이 이어지는가 vs 제자리인가**
```
내 코드 : 2 → 20 → 6,  2 → 20 → 6,  2 → 20 → 6 ...   (매번 제자리)
정답    : 2 → 20 → 6, 남은 2 → 20 → 6 ...            (이어짐)
```

**`1 / 7`로 비교하면 확실하다**

| 회차 | 정답 `r` | 출력 | 내 코드 `r` | 출력 |
|---|---|---|---|---|
| 1 | 10 | **1** | 10 | **1** |
| 2 | 30 | **4** | 10 | **1** |
| 3 | 20 | **2** | 10 | **1** |
| 4 | 60 | **8** | 10 | **1** |

**정답 — 초기화를 밖으로 빼고 `r %= B` 추가** ⭐
```python
A, B = map(int, input().split())

print(A // B, end='.')
r = A % B                    # ← 초기화: 반복문 밖에서 딱 한 번
for _ in range(20):
    r *= 10                  # ← 갱신: 반복문 안
    print(r // B, end='')
    r %= B                   # ← 다음 회차로 넘겨줄 값
print()
```

### 주의할 점
- ⚠️ **반복문 안에 변하지 않는 값(`A`, `B`)만으로 계산하는 줄이 있으면 의심하자.** 매번 같은 결과가 나온다는 뜻이다.
- 반복문 안에서 **누적·연결되어야 하는 변수**는 반드시 **밖에서 초기화**한다. (합계 `total = 0`, 카운트 `cnt = 0`도 똑같다)
- ⚠️ 이 버그는 **에러가 나지 않는다.** 출력 개수도 20개로 정확히 맞는다.
- **예제 1개만 맞춰 보고 넘어가면 놓친다.** `1 4`, `1 7`처럼 **자릿수가 서로 다른 값**을 꼭 넣어 보자.
- 자기 검증 습관: **"이 변수가 다음 회차에 바뀌어 있는가?"** 를 스스로 물어보기. 안 바뀌면 반복문을 쓰는 의미가 없다.
- `k = r // B` 처럼 한 번만 쓰는 변수는 두어도 되고, `print(r // B, end='')`로 바로 써도 된다. **이건 버그와 무관한 스타일 차이.**

## 8. 오류 정리 — 상태 변수를 결과값으로 덮어쓰지 않기

### 핵심 요약

- **내가 쓴 코드**

  ```python
  r = A % B
  for _ in range(20):
      r *= 10
      r = r // B      # ← 여기서 r이 "나머지"에서 "출력할 숫자"로 바뀐다
      print(r, end='')
      r %= B          # ← 나머지가 아니라 "숫자"를 다시 나눈 엉뚱한 값
  ```

- `r` 하나에 **역할이 다른 두 값**을 담으려 한 것이 문제다.
- `r = r // B`를 하는 순간 **나머지가 사라진다.** 그 뒤의 `r %= B`는 다음 회차에 쓸 나머지가 아니다.
- 7번(초기화 위치)과는 **다른 버그**다. 초기화는 밖으로 잘 뺐지만, 이번엔 **상태를 중간에 잃어버렸다.**
- 원칙 ⭐ **살아남아야 하는 값(상태)과, 쓰고 버리는 값(결과)은 변수를 나눈다.**

### 예시 코드

**14 ÷ 3 따라가기**

| 회차 | `r *= 10` | `r = r // B` (출력) | `r %= B` |
| --- | --- | --- | --- |
| 시작 | `r = 2` | — | — |
| 1 | 20 | **6** ← `r`이 6이 됨 | `6 % 3` = **0** ❌ |
| 2 | 0 | **0** | 0 |
| 3 | 0 | **0** | 0 |

```
내 출력 : 4.60000000000000000000
정답    : 4.66666666666666666666
```

**다른 입력은 더 이상하게 나온다**

```
 14/3   내 코드: 4.60000000000000000000   정답: 4.66666666666666666666
  1/7   내 코드: 0.11111111111111111111   정답: 0.14285714285714285714
  1/4   내 코드: 0.25252525252525252525   정답: 0.25000000000000000000
```

**두 값의 역할 구분**

| 값 | 역할 | 수명 |
| --- | --- | --- |
| **나머지** | 다음 회차로 넘길 **상태** | 끝까지 살아 있어야 함 |
| **몫(숫자)** | 이번에 출력할 **결과** | 쓰고 버림 |

**고친 코드 (1) — 몫을 바로 출력하고 버린다** ⭐

```python
r = A % B
for _ in range(20):
    r *= 10
    print(r // B, end='')    # 몫은 출력하고 버림
    r %= B                   # r은 끝까지 "나머지"로만 유지
```

**고친 코드 (2) — 몫을 별도 변수에 담는다**

```python
r = A % B
for _ in range(20):
    r *= 10
    k = r // B
    print(k, end='')
    r %= B
```

### 주의할 점

- ⚠️ **상태 변수에 `=`로 다른 값을 대입하는 순간**을 경계하자. 그 변수의 원래 의미가 사라진다.
- 변수 이름을 **역할대로** 지으면 실수가 줄어든다. `r`(나머지)에 몫을 넣는 건 이름과 어긋나는 일이다.
- 7번과 8번은 **증상이 비슷해도 원인이 다르다.** 둘 다 "반복문이 상태를 제대로 이어받는가"의 문제다.
  - 7번: 상태를 **매번 되돌림** (초기화가 안에 있음)
  - 8번: 상태를 **중간에 잃어버림** (다른 값으로 덮어씀)
- 확인 습관: 반복 1회가 끝난 시점에 **"이 변수는 지금 무슨 뜻인가?"** 를 말로 설명해 보기. 설명이 막히면 버그다.
- 여기서도 `14 3` 하나만 보면 `4.6000...`이라 그럴듯해 보인다. **`1 7`로 꼭 확인하자.**

## ✅ 한눈에 복습 체크리스트

- [ ] `;`는 **파이썬에서도 유효**하다. C/Java 전용이 아니다.
- [ ] C/Java의 `;` = **필수 종결 기호**, 파이썬의 `;` = **선택 구분자**(한 줄에 여러 문장).
- [ ] `q = 0; s = 1; t = 1` 은 세 줄로 나눠 쓴 것과 **완전히 동일**하다.
- [ ] 줄 끝에 붙인 `;`(`a = 1;`)는 **에러는 아니지만 의미 없는 군더더기**다.
- [ ] 파이썬다운 초기화는 **다중 대입** → `q, s, t = 0, 1, 1`
- [ ] `for` / `if` 같은 **블록 여는 문장은** `;`**로 못 붙인다** (SyntaxError).
- [ ] 파이썬은 `;`가 아니라 **줄바꿈과 들여쓰기가 문법**이다.
- [ ] 값을 밀어 주는 반복문은 **대입 순서**가 결과를 바꾼다. 표로 한 줄씩 굴려 보자.
- [ ] `range(start, stop, step)` — **크기가 아니라 적은 위치**가 역할을 정한다.
- [ ] **첫 번째 자리가 무조건 시작값.** `range(10, 4, -1)`은 10부터 시작한다.
- [ ] `-1`은 "순서를 뒤집어라"가 아니라 **"매번 -1을 더해라"**.
- [ ] 끝값(`stop`)은 **방향과 상관없이 항상 제외**된다. 감소면 `b + 1`까지 나온다.
- [ ] **5까지 출력하려면 stop에 4**를 적는다 (마지막 값보다 1 작게).
- [ ] ⚠️ `range(4, 10, -1)`은 **빈 range**. 작은 값을 알아서 앞에 놓아 주지 않는다.
- [ ] ⚠️ 감소인데 step을 빼먹으면 **에러 없이 0번 반복**한다.
- [ ] 헷갈리면 `print(list(range(...)))`로 숫자를 직접 확인하자.
- [ ] **start는 포함, stop만 제외.** "끝값 제외"를 양쪽에 다 적용하지 말 것.
- [ ] start에는 **절대 ±1을 하지 않는다.** 원하는 첫 값을 그대로 적는다.
- [ ] 감소 공식: `range(첫 값, 마지막 값 - 1, -1)` → 17~5이면 `range(17, 4, -1)`.
- [ ] `range(18, 5, -1)`은 `18~6`이 나온다. **양쪽이 한 칸씩 밀린 것.**
- [ ] 이 실수는 **에러가 안 나고 개수도 같다.** 값만 밀려서 놓치기 쉽다.
- [ ] 확인은 **첫 값과 마지막 값 둘만** 보면 된다.
- [ ] `print`의 `end` **기본값은** `"\n"` — 그래서 매번 줄이 바뀐다.
- [ ] 붙여 출력 → `end=""`, 한 칸 띄어 출력 → `end=" "`. 따옴표 사이를 확인!
- [ ] ⚠️ `end=""`로 끝내면 **줄바꿈이 없는 상태**다. 반복 후 `print()` 로 마무리.
- [ ] `sep`은 값들 **사이**, `end`는 **맨 끝**. (ch1 복습)
- [ ] 같은 문자 반복은 `print("A" * n)` 한 줄로도 된다.
- [ ] 반복 변수를 **안 쓰면** `_` — "이 값은 쓰지 않겠다"는 신호.
- [ ] `_`는 **문법이 아니라 관례**다. 평범한 변수라서 값도 실제로 들어간다.
- [ ] 판단 기준: **블록 안에서 그 변수를 읽는가?** 읽으면 `i`, 안 읽으면 `_`.
- [ ] 파이썬 float는 **유효숫자 약 17자리**가 한계다. 그 너머는 **쓰레기값**이다.
- [ ] `A/B`를 계산하는 **순간 값이 변질**된다. `:.20f`로 늘려도 정확도는 안 생긴다.
- [ ] ⚠️ 소수 **17자리 이상**을 요구하면 `/`**와** `:.Nf`**는 금지** 신호.
- [ ] `:.Nf`는 **반올림**이다. "내림"을 요구하면 쓰면 안 된다.
- [ ] 해결: **정수 연산(**`//`**,** `%`**)으로 한 자리씩** 만드는 **긴 나눗셈 반복문**.
- [ ] 긴 나눗셈 3줄: `r *= 10` **→** `print(r // B, end='')` **→** `r %= B`
- [ ] 이건 **초등학교 세로셈 그대로**다. `r *= 10` = **"0을 내려쓴다"**.
- [ ] `A/B` = `A//B` + `(A%B)/B` — 정수부를 떼면 **남는 건 `r/B` 분수뿐**이다.
- [ ] `r < B`라서 `r/B`는 **0~1 사이**. ×10 하면 **다음 자리가 정수부로 올라온다.**
- [ ] 버리는 것이 곧 **내림**이라 따로 처리할 게 없다.
- [ ] `Decimal`을 쓸 땐 `Decimal(A) / Decimal(B)` — `Decimal(A/B)`는 이미 늦었다.
- [ ] 앞 16자리는 맞게 나오므로 **예제 하나만 보고 넘어가면 놓친다.**
- [ ] ⭐ **초기화는 반복문 밖, 갱신은 반복문 안.**
- [ ] 반복문 안에서 **안 변하는 값(`A`, `B`)만으로 계산하는 줄**은 의심하자 → 매번 같은 결과.
- [ ] 긴 나눗셈에서 **`r %= B`** 가 빠지면 **같은 숫자만 20번** 찍힌다.
