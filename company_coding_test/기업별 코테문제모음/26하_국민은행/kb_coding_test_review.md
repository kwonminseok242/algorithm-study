## 1번. R/L 조건 필터링

### 문제
`"방향 값1 값2 값3"` 형식의 문자열 배열이 주어진다. 방향(`R`/`L`)별 조건을 모두 만족하는 원소의 인덱스를 오름차순으로 반환한다.

### 조건 (예제 답으로 역검증 완료)

| 조건 | R | L |
|---|---|---|
| ① 값2 범위 | 30 ≤ 값2 ≤ 70 | 50 ≤ 값2 ≤ 120 |
| ② 값3 범위 | 값2 ÷ 2 ≤ 값3 ≤ 값2 | 동일 |
| ③ 세 값의 합 | ≥ 200 | ≥ 350 |

### 예제
```
입력: ["R 150 40 25", "L 230 80 50", "R 100 75 60", "R 140 50 20", "L 240 70 40"]
출력: [0, 1, 4]
```
- 2번: R인데 값2 = 75 > 70 → ① 위반
- 3번: 값2 ÷ 2 = 25 > 값3 = 20 → ② 위반
- 4번: 합 = 350 ≥ 350 → 경계값 포함 통과

### 풀이
```python
def solution(items):
    rule = {"R": (30, 70, 200), "L": (50, 120, 350)}
    res = []
    for i, s in enumerate(items):
        side, a, b, c = s.split()
        a, b, c = int(a), int(b), int(c)
        lo, hi, need = rule[side]
        if lo <= b <= hi and b <= 2 * c and c <= b and a + b + c >= need:
            res.append(i)
    return res
```
- 경계값(≤, ≥) 포함 여부 주의

### 왜 `b / 2 <= c` 대신 `b <= 2 * c`인가
양변에 2를 곱해 나눗셈을 없애면 정수끼리만 비교하게 되어 언어와 관계없이 항상 정확하다.

- **정수 나눗셈 언어 (Java, C++, C)**: `b / 2`는 소수점을 버린다. b = 41, c = 20이면 실제로는 20.5 ≤ 20이 거짓이어야 하는데, `41 / 2 = 20`이 되어 `20 <= 20`이 참으로 통과한다. 값2가 홀수일 때만 틀리므로 예제는 통과하고 히든 케이스에서 틀리기 쉬운 전형적인 함정.
- **Python 2 / `//` 사용 시**: 같은 이유로 버림이 발생한다.
- **Python 3의 `/`**: 실수 나눗셈이고 2로 나누는 건 이진 부동소수점에서 정확하게 표현되므로 이 문제에서는 실제로 틀리지 않는다. 다만 `/ 3`, `* 0.1`처럼 정확히 표현되지 않는 연산으로 바뀌면 `0.1 + 0.2 != 0.3` 같은 오차로 경계값 비교가 틀릴 수 있다.

정리하면, 비교식의 나눗셈은 곱셈으로 옮겨 정수 비교로 만드는 습관을 들이면 언어나 연산이 바뀌어도 안전하다.

## 2번. 0인 칸 채우기 (8방향)

### 문제
정수 격자 `grid`와 정수 `k`가 주어진다. 값이 0인 칸을 다음 규칙으로 채운 격자를 반환한다.

1. 0인 칸의 주변 8방향(상하좌우 + 대각선) 이웃 중 **0이 아닌 수**를 모은다.
2. 그 수들을 **숫자 기준 오름차순** 정렬한 뒤 문자열로 이어 붙여 하나의 수로 만든다.
3. 그 수를 k로 나눈 **나머지 + 1**을 해당 칸의 값으로 넣는다.
4. 주변 8칸이 모두 0(또는 격자 밖)이면 **-1**을 넣는다.

### 예제
```
입력: grid = [[3,1,2,4],[0,0,12,2],[5,6,0,2],[9,10,1,9]], k = 7
출력:        [[3,1,2,4],[6,1,12,2],[5,6,4,2],[9,10,1,9]]
```

| 칸 | 0이 아닌 이웃 (정렬) | 이어 붙인 수 | % 7 | + 1 |
|---|---|---|---|---|
| (1,0) | 1, 3, 5, 6 | 1356 | 5 | **6** |
| (1,1) | 1, 2, 3, 5, 6, 12 | 1235612 | 0 | **1** |
| (2,2) | 1, 2, 2, 6, 9, 10, 12 | 122691012 | 3 | **4** |

### 예제로 확인되는 함정
- **숫자 정렬 vs 문자열 정렬**: (1,1)을 문자열 정렬하면 `"1","12","2",…` → 1122356 → % 7 + 1 = 5가 되어 틀린다. 반드시 정수로 정렬한 뒤 이어 붙인다.
- **원본 격자 기준으로 계산**: (1,1)을 계산할 때 이웃 (1,0)은 이미 6으로 바뀐 값이 아니라 원래 값 0으로 봐야 예제 답 1이 나온다. 결과는 복사본에 쓰고 판정은 원본으로 한다.
- **이어 붙인 수가 매우 커질 수 있음**: 이웃이 최대 8개라 자릿수가 커진다. Python은 큰 정수가 자연스럽지만, Java/C++에서는 오버플로가 나므로 한 자리씩 붙이며 나머지를 누적한다 (`m = (m * 10 + digit) % k`).

### 풀이
```python
DIRS = [(dr, dc) for dr in (-1, 0, 1) for dc in (-1, 0, 1) if (dr, dc) != (0, 0)]

def get_adj(grid, r, c):
    """(r, c) 주변 8칸의 0이 아닌 수를 숫자 기준 정렬 후 이어 붙인 문자열, 모두 0이면 False"""
    H, W = len(grid), len(grid[0])
    nums = sorted(grid[r + dr][c + dc] for dr, dc in DIRS
                  if 0 <= r + dr < H and 0 <= c + dc < W and grid[r + dr][c + dc] != 0)
    s = ''.join(map(str, nums))   # 두 자리 수도 그대로 이어 붙임 (예: 12 → "12")
    return s if s != '' else False

def solution(grid, k):
    res = [row[:] for row in grid]
    for r in range(len(grid)):
        for c in range(len(grid[0])):
            if grid[r][c] != 0:
                continue
            adj = get_adj(grid, r, c)   # 원본 grid 기준
            if adj:
                res[r][c] = int(adj) % k + 1
            else:
                res[r][c] = -1
    return res
```
- 8방향은 `dr, dc ∈ {-1, 0, 1}`에서 `(0, 0)`만 제외하면 된다 (`DIRS`).
- `get_adj`는 한 번만 호출해 변수에 담고 분기한다. `if get_adj(...)` 안에서 다시 호출하면 같은 계산을 두 번 하게 된다.
- `get_adj`에 항상 원본 `grid`를 넘기고 결과는 `res`에만 써서 원본/복사본을 분리한다.
- 정렬은 반드시 문자열로 바꾸기 **전에** 정수 상태에서 한다. `map(str, …)` 후 정렬하면 문자열 정렬이 되어 (1,1)이 틀린다.
- 복잡도 O(HW · 8 log 8) = O(HW).

## 3번. 관객 탈출 최소 시간

### 문제
H×W 크기의 `hall`이 주어진다.

| 값 | 의미 |
|---|---|
| -1 | 장애물 |
| 0 | 빈칸 |
| 1 | 관객 |

모든 관객이 출구로 빠져나가는 데 걸리는 **최소 시간**을 구한다.

### 조건
- 가장자리 칸 중 **정확히 하나만 빈칸**이고, 그곳이 출구다.
- 관객 수는 1보다 크다.
- 매 시점 각 관객은 상하좌우로 한 칸 이동하거나 **제자리에서 대기**할 수 있다.
- 한 칸에는 한 명만 있을 수 있다.
- 앞사람이 비운 칸에 **같은 시점에 뒷사람이 따라 들어갈 수 있다.**
- TODO: 출구 칸 도착 = 탈출인지, 출구 칸에서 한 시점 더 필요한지

### 내 풀이 (시험 당시)
1. 가장자리를 돌며 출구 찾기
2. 출구에서 BFS 한 번으로 모든 칸의 출구까지 거리 계산
3. 매 시점 관객을 거리순으로 정렬해 가까운 사람부터 한 칸씩 이동하는 시뮬레이션

### 핵심 관찰
**병목은 출구 하나뿐이라고 봐도 된다.**

중간 합류 지점에서도 대기는 실제로 발생하지만, 그 지연은 어차피 출구에서 겪을 지연을 앞당겨 겪는 것일 뿐이라 답이 바뀌지 않는다.

거리를 오름차순으로 d₀ ≤ d₁ ≤ … ≤ dₙ₋₁ 로 정렬하면 i번째 사람의 탈출 시각은

```
t_i = max(d_i, t_{i-1} + 1)
```

- `d_i`: 방해 없이 출구에 도착할 수 있는 가장 빠른 시각
- `t_{i-1} + 1`: 출구는 시점당 한 명만 통과 → 앞사람 바로 다음 시각

정리하면 `answer = max(d_i + (n - 1 - i))`.

### 왜 중간 병목이 답을 안 바꾸나 (증명 스케치)
- 공식으로 구한 탈출 시각 t₀ < t₁ < … 는 모두 다르다.
- i번째 사람에게 "시점 τ에는 출구로부터 거리 `t_i − τ`인 칸에 있어라 (출발 거리보다 크면 출발 칸에서 대기)"라는 일정을 준다.
- 동시에 움직이는 두 사람은 `t_i`가 달라서 항상 다른 거리 → 같은 칸에 있을 수 없다.
- 대기 중인 사람의 출발 칸을 지나가려면 출발 거리가 더 커야 하는데, 그런 사람은 정렬상 뒤 순서라 더 늦게 그 거리에 도달한다.
- 따라서 충돌 없는 일정이 항상 존재 → 공식 값이 달성 가능한 최솟값.

### 예제로 확인

**예제 1: 거리 [1, 2, 2, 2, 3]**

| 사람 | d | 앞사람 t + 1 | 실제 t | 결정 요인 |
|---|---|---|---|---|
| 1 | 1 | 0 | 1 | 거리 |
| 2 | 2 | 2 | 2 | 거리 |
| 3 | 2 | 3 | 3 | 병목 |
| 4 | 2 | 4 | 4 | 병목 |
| 5 | 3 | 5 | 5 | 병목 (중복 거리가 아니어도 지연 전파) |

답: 5

**예제 2: 중간 합류 병목**

빈칸: (2,0)=출구, (2,1), (2,2), (1,2), (3,2), (1,3), (3,3) / 관객: (1,3), (3,3)

| 시점 | A | B | 비고 |
|---|---|---|---|
| 0 | (1,3) | (3,3) | 둘 다 거리 4 |
| 1 | (1,2) | (3,2) | |
| 2 | (2,2) | (3,2) 대기 | 합류 지점 병목 |
| 3 | (2,1) | (2,2) | |
| 4 | 탈출 | (2,1) | |
| 5 | | 탈출 | |

공식: 4 → max(4, 5) = **5**, 시뮬레이션과 일치.

### 정답 코드
```python
from collections import deque

def solution(hall):
    H, W = len(hall), len(hall[0])
    ex = next((r, c) for r in range(H) for c in range(W)
              if (r in (0, H - 1) or c in (0, W - 1)) and hall[r][c] == 0)

    dist = [[-1] * W for _ in range(H)]
    dist[ex[0]][ex[1]] = 0
    q = deque([ex])
    while q:
        r, c = q.popleft()
        for nr, nc in ((r + 1, c), (r - 1, c), (r, c + 1), (r, c - 1)):
            if 0 <= nr < H and 0 <= nc < W and hall[nr][nc] != -1 and dist[nr][nc] == -1:
                dist[nr][nc] = dist[r][c] + 1
                q.append((nr, nc))

    ds = sorted(dist[r][c] for r in range(H) for c in range(W) if hall[r][c] == 1)
    t = -1
    for d in ds:
        t = max(d, t + 1)
    return t
```
- 복잡도 O(HW + n log n). 거리 최대값이 HW이므로 카운팅으로 O(HW)도 가능.
- heap 불필요: 우선순위(거리)가 BFS 후 고정되어 바뀌지 않으므로 정렬 한 번이면 충분.

### 검증
- 최대 6×6 무작위 맵, 관객 2~4명, 관객 위치 조합 전체를 상태로 하는 BFS(브루트포스)와 비교
- 따라 들어가기 허용 규칙: 정렬 공식 **불일치 0건**
- 시험 때 방식(매 시점 거리순 정렬 후 한 명씩 이동, 점유 즉시 갱신): **1347건 중 불일치 0건**
- 따라 들어가기 금지 규칙으로 구현하면: 3000건 중 **1121건 불일치**

### 오답 원인 후보
1. **점유 판정을 이동 전 상태 기준으로 함** (가장 유력)
   매 시점 시작 시 위치 집합으로 "다음 칸이 비었나"를 검사하면, 앞사람이 비운 칸에 뒷사람이 못 들어가 줄이 한 시점씩 늦게 당겨진다. 일렬로 서는 상황만 있어도 답이 커짐.
   ```
   # # # # # #
   # . # P P #     출구 E, 관객 P
   # # # # E #     정답 2, 이동 전 기준 구현 시 3
   ```
2. **출구 처리 off-by-one**: 출구 칸 도착 시점 vs 한 시점 뒤 탈출. (예제를 통과했다면 가능성 낮음)
3. **시간 초과**: 매 시점 정렬 + 이동 시뮬레이션은 O((HW + n) · n log n)까지 커질 수 있음.

## 4번. 동시 접속 IP

### 문제
같은 날 같은 사용자가 **서로 다른 IP 2개 이상**으로 로그인한 경우를 찾는다.

### 풀이
```sql
SELECT DATE(LOGIN_AT) AS LOGIN_DATE, USER_ID
FROM LOGIN_HISTORY
GROUP BY DATE(LOGIN_AT), USER_ID
HAVING COUNT(DISTINCT IP_ADDRESS) >= 2
ORDER BY LOGIN_DATE, USER_ID;
```
- `COUNT(IP_ADDRESS)`가 아니라 `COUNT(DISTINCT IP_ADDRESS)`: 같은 IP로 여러 번 로그인한 경우 제외
- 날짜 단위 집계를 위해 `DATE()`로 시간 부분 제거
