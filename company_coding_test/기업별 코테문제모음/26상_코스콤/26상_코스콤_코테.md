## 알고리즘 #1. 디스크 컨트롤러 `골드 4?`

프로그래머스 Lv 3 - [문제 링크](https://school.programmers.co.kr/learn/courses/30/lessons/42627)

> 원문을 그대로 옮기지 않고 요약했다. 정확한 지문은 링크에서 확인.

### 문제
하드디스크는 한 번에 하나의 작업만 처리할 수 있고, 요청된 작업은 번호·요청 시각·소요 시간과 함께 대기 큐에 들어간다. 디스크가 쉬고 있고 대기 큐에 작업이 있으면 아래 우선순위로 하나를 꺼내 끝까지 처리한다 (중간에 끊지 않음).

1. 소요 시간이 짧은 작업
2. 같다면 요청 시각이 빠른 작업
3. 그것도 같다면 작업 번호가 작은 작업

작업이 끝난 바로 그 시각에 다음 작업을 시작할 수 있고, 같은 시각에 들어온 요청도 대기 큐에 포함된다. **반환 시간 = 종료 시각 − 요청 시각**이며, 모든 작업의 반환 시간 평균의 정수 부분을 반환한다.

| 입력 | 의미 |
|---|---|
| `jobs[i] = [요청 시각, 소요 시간]` | 인덱스 i가 작업 번호 |

**제한 사항**
- `jobs` 길이: 1 이상 500 이하
- 요청 시각: 0 이상 1,000 이하
- 소요 시간: 1 이상 1,000 이하

### 예제
```
입력: [[0, 3], [1, 9], [3, 5]]
출력: 8
```

| 작업 | 요청 | 시작 | 종료 | 반환 시간 |
|---|---|---|---|---|
| 0번 | 0 | 0 | 3 | 3 |
| 2번 | 3 | 3 | 8 | 5 |
| 1번 | 1 | 8 | 17 | 16 |

- 3ms에 0번이 끝날 때 대기 큐에는 1번(9ms)과 방금 들어온 2번(5ms)이 있다 → 더 짧은 2번 먼저
- 평균 = (3 + 5 + 16) / 3 = 8

### 풀이
```python
import heapq

def solution(jobs):
    n = len(jobs)
    order = sorted(range(n), key=lambda i: jobs[i][0])   # 요청 시각순 작업 번호
    pq = []
    t = total = idx = done = 0
    while done < n:
        # 현재 시각까지 요청된 작업을 모두 대기 큐에 넣는다 (같은 시각 포함)
        while idx < n and jobs[order[idx]][0] <= t:
            i = order[idx]
            heapq.heappush(pq, (jobs[i][1], jobs[i][0], i))   # (소요, 요청, 번호)
            idx += 1
        if pq:
            d, r, i = heapq.heappop(pq)
            t += d
            total += t - r
            done += 1
        else:
            t = jobs[order[idx]][0]   # 쉬는 동안은 다음 요청 시각으로 점프
    return total // n
```
- 힙 원소를 `(소요 시간, 요청 시각, 번호)` 튜플로 넣으면 튜플 비교만으로 3단계 우선순위가 그대로 구현된다.
- 복잡도 O(n log n).

### 함정
- **유휴 시간 처리**: 대기 큐가 비었는데 남은 작업이 있으면 다음 요청 시각으로 시간을 옮겨야 한다. `t += 1`로 한 칸씩 올려도 답은 맞지만 불필요하게 돈다.
- **`<=` 비교**: 작업이 끝난 시각과 같은 시각에 들어온 요청도 후보다. `<`로 쓰면 예제의 2번 작업을 놓쳐 1번을 먼저 처리하게 된다.
- **입력이 요청 시각순이라는 보장이 없다**: 반드시 정렬 후 처리.
- **지문 버전 차이**: 예전 지문은 "평균을 가장 줄이는 방법"을 찾게 했고 예제가 `[[0,3],[1,9],[2,6]] → 9`였다. 현재 지문은 우선순위 규칙을 명시한다. 위 코드는 두 예제 모두 통과.

## 알고리즘 #2. 자릿수 합 연산으로 만들 수 있는 최솟값 `골드 3 ~ 골드 2`

### 문제
양의 정수 x에 아래 연산을 0번 이상 수행했을 때 만들 수 있는 수들 중 가장 작은 값을 구한다.

1. `|x − y| = s(x) + s(y)`를 만족하는 음이 아닌 정수 y를 찾는다.
2. 찾았다면 x를 `|x − y|`로 바꾼다.

- `s(n)`: n의 각 자릿수의 합 (예: `s(403) = 7`, `s(101) = 2`, `s(222) = 6`)
- 제약: `1 ≤ x ≤ 1,000,000,000`
- TODO: 반환 형식, 다른 제약 조건이 있었는지 확인

### 예제
```
입력: 75
출력: 12
```

| 단계 | x | y | s(x) | s(y) | \|x − y\| |
|---|---|---|---|---|---|
| 1 | 75 | 54 | 12 | 9 | 21 |
| 2 | 21 | 9 | 3 | 9 | 12 |
| 3 | 12 | 없음 | | | |

### 핵심 관찰
**1. y는 x 근처에만 있다.**
`|x − y| = s(x) + s(y)`이고, y < 2 × 10⁹ 범위에서 `s(y) ≤ 82`이므로 `|x − y| ≤ s(x) + 90`이다. 따라서 y 후보는 `[x − D, x + D]` (D = s(x) + 90) 안에서만 찾으면 된다. x가 10억이어도 후보는 수백 개뿐.

**2. 한 번 바뀌면 값이 작아진다.**
바뀐 값은 `s(x) + s(y)`이므로 많아야 81 + 90 정도다. 첫 연산 이후 등장하는 수는 모두 작은 범위에 갇혀서 상태 수가 적다.

**3. y가 여러 개일 수 있으니 전부 탐색한다.**
처음 찾은 y로만 진행하면 최솟값을 놓칠 수 있다. 가능한 모든 y로 갈라지는 경로를 BFS로 탐색하고, 방문한 수는 다시 보지 않는다 (순환 방지).

### 풀이
```python
from collections import deque

def s(n):
    return sum(map(int, str(n)))

def solution(x):
    best = x
    seen = {x}
    q = deque([x])
    while q:
        cur = q.popleft()
        best = min(best, cur)
        sc = s(cur)
        D = sc + 90
        for y in range(max(0, cur - D), cur + D + 1):
            nxt = abs(cur - y)
            if nxt == sc + s(y) and nxt not in seen:
                seen.add(nxt)
                q.append(nxt)
    return best
```
- 상태당 후보 y는 약 2D ≤ 2 × 171개, 상태 수는 첫 연산 이후 수백 개 이하 → 충분히 빠르다.

### 추가 관찰: mod 9로 후보 줄이기
n ≡ s(n) (mod 9)를 이용하면 후보를 더 줄일 수 있다.

- **y < x인 경우**: `x − s(x) = y + s(y)` → 좌변은 9의 배수, 우변은 2y (mod 9) → **y는 9의 배수**여야 한다. (예제의 54, 9 모두 9의 배수)
- **y > x인 경우**: `y − s(y) = x + s(x)` → 좌변은 9의 배수, 우변은 2x (mod 9) → **x가 9의 배수**일 때만 가능하다.

필수는 아니지만 면접이나 풀이 설명에서 근거로 쓰기 좋다. 무작위 3,000건에서 전체 탐색 결과와 일치함을 확인했다.

### 함정
- **x 전체 범위를 순회하면 시간 초과**: y 범위를 `s(x) + 90`으로 묶는 게 핵심.
- **y < x만 보면 안 된다**: 절댓값이므로 y > x 쪽도 확인해야 한다.
- **0번 연산도 포함**: 연산이 불가능하면 x 자체가 답이다.

## SQL #1. 부서·성별 마라톤 1등 `Lv 3?`

### 문제
`MARATHON_RESULTS` 테이블에서 부서별·성별로 `MARATHON_RANK`가 가장 높은 사람(숫자가 가장 작은 사람)의 `DEPT`, `GENDER`, `EMP_ID`를 출력한다. `DEPT`, `GENDER` 순으로 정렬한다.

- `MARATHON_RANK`는 모두 고유한 등수를 가진다.

| EMP_ID | DEPT | GENDER | MARATHON_RANK |
|---|---|---|---|
| 101 | HR | M | 4 |
| 102 | DEV | F | 3 |
| 103 | DEV | M | 9 |
| 104 | SALES | F | 8 |
| 105 | HR | F | 10 |
| 106 | MARKETING | M | 5 |
| 107 | MARKETING | M | 2 |
| 108 | HR | F | 7 |
| 109 | MARKETING | M | 1 |
| 110 | SALES | F | 6 |

### 예제

| DEPT | GENDER | EMP_ID |
|---|---|---|
| DEV | F | 102 |
| DEV | M | 103 |
| HR | F | 108 |
| HR | M | 101 |
| MARKETING | M | 109 |
| SALES | F | 110 |

### 풀이 1 - JOIN (시험 당시 풀이)
```sql
SELECT R1.DEPT, R1.GENDER, R1.EMP_ID
FROM MARATHON_RESULTS R1
JOIN (
    SELECT DEPT, GENDER, MIN(MARATHON_RANK) AS MIN_MARATHON_RANK
    FROM MARATHON_RESULTS
    GROUP BY DEPT, GENDER
) R2
ON R1.MARATHON_RANK = R2.MIN_MARATHON_RANK
ORDER BY R1.DEPT, R1.GENDER;
```

### 풀이 2 - 윈도우 함수
```sql
SELECT DEPT, GENDER, EMP_ID
FROM (
    SELECT DEPT,
           GENDER,
           EMP_ID,
           ROW_NUMBER() OVER (
               PARTITION BY DEPT, GENDER
               ORDER BY MARATHON_RANK
           ) AS RN
    FROM MARATHON_RESULTS
) T
WHERE RN = 1
ORDER BY DEPT, GENDER;
```

### 포인트
- **GROUP BY만으로는 EMP_ID를 못 가져온다**: `MIN()`은 최솟값만 주고 그 행의 다른 컬럼은 주지 않는다. 그래서 JOIN으로 원래 행을 다시 찾거나 윈도우 함수로 순위를 매긴다.
- **JOIN 조건**: 등수가 전체에서 고유하므로 `MARATHON_RANK`만으로 조인해도 정답이다. 다만 등수가 그룹 안에서만 고유한 경우까지 대비하면 `R1.DEPT = R2.DEPT AND R1.GENDER = R2.GENDER`도 함께 거는 것이 안전하다.
- **ROW_NUMBER vs RANK**: 동점이 있다면 `ROW_NUMBER`는 한 명만, `RANK`는 동점자 전원을 남긴다. 이 문제는 등수가 고유해서 결과가 같다.

## 정리
- 알고리즘 1번은 힙 튜플 순서와 유휴 시간 처리, 같은 시각 요청(`<=`)이 포인트.
- 알고리즘 2번은 연산 조건에서 y의 범위를 묶어내는 게 핵심. 범위만 잡히면 작은 상태 공간 BFS로 끝난다.
- SQL은 "그룹별 최댓값/최솟값을 가진 **행**"을 찾는 전형 문제. JOIN과 윈도우 함수 두 방식 모두 익혀두기.
