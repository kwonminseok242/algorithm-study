# Q2. 로봇청소기 최소 k

## 문제 조건

- `n × n` 격자 구역
- `robots` : 로봇청소기들의 좌표 배열
- `walls` : `(r1, c1, r2, c2)` 리스트. `(r1,c1)`과 `(r2,c2)` 사이 이동이 **막힘 (양방향)**
- 로봇은 자신으로부터 거리 `k` 이내의 구역을 방문할 수 있음
- **모든 구역이 로봇 중 어느 하나에게라도 방문되는** 최소 `k`를 구하라

> 각 로봇이 각자 전부 방문해야 하는 게 아니라, **어느 하나라도** 커버하면 된다.
> → 멀티소스 BFS가 정확히 이 조건을 푼다.

---

## 접근

모든 로봇 좌표를 **한꺼번에 큐에 넣고 BFS**를 돌리면,
각 칸에는 "가장 가까운 로봇까지의 최단 거리"가 기록된다.
그 값들의 **최댓값**이 모든 칸을 커버하는 데 필요한 최소 `k`다.

```python
from collections import deque

def solve(n, robots, walls):
    # 벽은 반드시 양방향으로 등록
    blocked = set()
    for r1, c1, r2, c2 in walls:
        blocked.add((r1, c1, r2, c2))
        blocked.add((r2, c2, r1, c1))     # ← 이 줄이 핵심

    # 시작점을 1로 두어 0을 '미방문' 표시로 겸용
    dist = [[0] * n for _ in range(n)]
    queue = deque()
    for r, c in robots:
        dist[r][c] = 1
        queue.append((r, c))

    while queue:
        r, c = queue.popleft()
        for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
            nr, nc = r + dr, c + dc
            if not (0 <= nr < n and 0 <= nc < n):
                continue
            if (r, c, nr, nc) in blocked:
                continue
            if dist[nr][nc] != 0:          # 이미 방문
                continue
            dist[nr][nc] = dist[r][c] + 1
            queue.append((nr, nc))

    answer = 0
    for row in dist:
        if 0 in row:
            return -1                      # 도달 불가 칸 존재 (지문 규정에 맞게 처리)
        answer = max(answer, max(row))
    return answer - 1                      # 1로 시작했으므로 1을 뺀다
```

## 체크포인트

### 1. 멀티소스 BFS 선택 — ✅ 정확

"어느 하나라도 방문" 조건이므로 모든 로봇을 동시에 큐에 넣는 게 맞다.

만약 지문이 "**각** 로봇이 모든 칸을 방문"이었다면 완전히 다른 문제가 된다.
그때는 로봇마다 개별 BFS를 돌려 `(로봇, 칸)` 쌍의 최대 거리를 구해야 하고,
멀티소스 결과는 항상 그보다 작게 나온다.

### 2. 마지막 `-1` — ✅ 정확

`dist` 배열을 `0`으로 초기화하고 `0`을 미방문 표시로 썼기 때문에
시작점을 `1`로 두는 것이 자연스럽다. 이 경우 실제 거리는 기록값보다 1 크므로
**최댓값에서 1을 빼는 것이 맞다.**

| 초기화 방식 | 시작점 값 | 마지막 처리 |
|---|---|---|
| `0`으로 채우고 0=미방문 | `1` | `max - 1` ✅ (이번 풀이) |
| `-1`로 채우고 -1=미방문 | `0` | `max` 그대로 |

두 방식을 섞으면 off-by-one이 난다.

### 3. 벽 양방향 처리 — ❌ **실제 버그**

`blocked` 집합에 `(r1,c1,r2,c2)` **한 방향만** 넣고
`(r, c, nr, nc) in blocked`로 검사했다면, 반대 방향 통과가 그대로 뚫린다.

#### 왜 결과가 틀어지는가
BFS는 어느 쪽 칸에 먼저 도달하느냐가 상황마다 다르다.
로봇이 `(r2,c2)` 쪽에서 먼저 도달하면 `(r2,c2) → (r1,c1)` 이동이 막히지 않고 통과한다.

→ **실제보다 짧은 거리가 기록되고, 답 `k`가 정답보다 작게 나온다.**

#### 증상 패턴
- 벽이 없거나 경로에 영향을 주지 않는 케이스 → **통과**
- 벽이 실제로 우회를 강제하는 케이스 → **오답**
- 따라서 부분 점수는 나왔을 가능성이 크다.

#### 수정
넣을 때 대칭으로 넣는다. (검사할 때마다 두 번 확인하는 것보다 실수가 적다)

```python
blocked.add((r1, c1, r2, c2))
blocked.add((r2, c2, r1, c1))
```

또는 인접 리스트 형태로:

```python
from collections import defaultdict
blocked = defaultdict(set)
for r1, c1, r2, c2 in walls:
    blocked[(r1, c1)].add((r2, c2))
    blocked[(r2, c2)].add((r1, c1))
# 검사: if (nr, nc) in blocked[(r, c)]: continue
```

### 4. 도달 불가 칸 처리

벽 배치에 따라 어떤 칸도 도달하지 못할 수 있다.
BFS 종료 후 `0`이 남아 있는 칸이 있으면 그 경우의 규정(`-1` 반환 등)을 따라야 한다.
이 처리가 없으면 미방문 칸이 `0`이라 `max` 계산에 조용히 묻혀 오답이 된다.
